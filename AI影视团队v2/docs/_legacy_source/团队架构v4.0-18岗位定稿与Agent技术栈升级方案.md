## 0. 结论速览

| 项 | v3.0 | v4.0 | 依据 |
|---|---|---|---|
| 岗位总数 | 14 | **18**（+4新增，0删减） | 现实剧组6大组职能齐全 + 老板"再加人、专业化、对口化"指令 |

## 2. 架构定稿：18岗位组织结构（对齐现实剧组6大组）

```
【决策组】制片人 ── 统筹/执行制片
【创作组】编剧 ── 艺术总监 ── 分镜师 ── 作曲*
【美术资产组】角色设计师 ── 服装造型师* ── 置景设计师 ── 道具师
【摄影生成组】摄影指导 ── 灯光师 ── 动画师
【后期技术组】视效师* ── 调色师 ── 剪辑师
【声音组】声音设计师
【全流程质控】场记/质检
```
（* = v4.0新增岗位）

**主工序链**（素材流）：
编剧→(艺术总监风格审)→分镜师→[摄影指导开拍单参数+灯光师布光+美术资产组参考资产]→动画师生成→**视效师技术增强→调色师→剪辑师**（v4.0新工序链）→场记质检全程把关→统筹调度全程派单
**声音支线**：编剧台词→作曲配乐+声音设计师对白/音效/环境→声音设计师终混→剪辑师合入

## 3. 四个新增岗位JD（均有独立工具链支撑）

### 3.1 服装造型师（Costume Designer & Stylist）｜优先级：高

| 项 | 定义 |
|---|---|
| 现实原型 | 服装设计师 Costume Designer + 化妆造型师 Makeup & Hair（现实剧组美术组标配两岗，AI流程合一） |
| 核心职责 | ①角色服装/妆容/发型资产设计与**跨镜一致性**（服装lock字段写入character_lock）②逐场换装设定（costume sheet）③改装/换装参考图生成（供Ref2VA/首尾帧引擎挂载） |
| 工具链 | 本地**CatVTON**（8GB显存可跑，ComfyUI有Wrapper节点）／IDM-VTON备选（4.6k stars，许可未验证）／FLUX Kontext指令改服装（已列P1部署）／云端OutfitAnyone-Plus API（阿里云2026-09在架，商用备选） |
| 交接物 | 服装造型表（每角色×每场）+ 服装参考图集 + character_lock服装字段 |
| 边界 | 角色设计师管"这个人长什么样"（脸/身材/身份锚点），服装造型师管"穿什么+妆发"；v3.0由角色设计师兼任服装，v4.0拆分——林小雨短发跑形修3轮的教训证明服装发型是独立战斗 |

> **许可证警示**：CatVTON为 CC BY-NC-SA 4.0（**非商用**）——阶段0-1内部打样可用，商业化阶段（阶段3接单）必须换OutfitAnyone API或获授权。此约束已列入拍板项。

### 3.2 作曲（Composer）｜优先级：中高

| 项 | 定义 |
|---|---|
| 现实原型 | 作曲 Composer + 音乐监督 Music Supervisor（小剧组合一） |
| 核心职责 | ①主题音乐设计（主旋律/情绪动机，如雨夜寻猫C4-E4-G4-A4主题）②逐场配乐与音乐叙事弧线（首现/展开/高潮/淡出的时间轴设计）③BGM生成 |
| 工具链 | **ACE-Step v1.5**（P0部署，ComfyUI原生AIO单文件<4GB，tag驱动支持纯音乐）；gen_bgm.py程序合成为零成本兜底（管线不变，归属从声音设计师移交作曲） |
| 交接物 | 配乐清单（music cues：场次/入点/时长/情绪tag）+ BGM音轨文件 |
| 边界 | 声音设计师管"声音世界"（对白/音效/环境/终混），作曲管"音乐"；作曲产出BGM交声音设计师进终混——与现实剧组声音部门内部协作一致 |

### 3.3 视效师（VFX & DI Artist）｜优先级：高（阶段0即需，口型同步）

| 项 | 定义 |
|---|---|
| 现实原型 | 视效总监 VFX Supervisor + 视效师 + DI工程师（AI流程中审核职能归场记/艺术总监，执行职能独立成岗） |
| 核心职责 | 生成素材的**技术增强与修复**：①视频超分②补帧/去闪③物体移除/去水印④**口型同步**⑤画面稳定⑥场记退回的技术类问题修复 |
| 工具链 | 超分：**FlashVSR**（单步流式，低显存友好，MIT待验证）／SeedVR2（字节，显存未验证）备选；补帧：**RIFE**（ComfyUI v0.20.1+原生节点）；口型：**MuseTalk 1.5**（约8GB，MIT，ComfyUI-MuseTalk节点）主选+Wav2Lip低质备选；物体移除：ProPainter（P2）；转写辅助：faster-whisper/SenseVoice |
| 交接物 | 增强后素材（K13新版本）+ 处理日志（用了什么工具/参数） |
| 边界 | **工序链定稿：动画师→视效师→调色师→剪辑师**（VFX在调色前，与现实后期流程一致）。动画师生成原始素材不做技术修复；调色师只管色彩不做修复 |

> **12GB显存瓶颈警示**（工具调研实测结论）：LatentSync约18GB**跑不动**；EchoMimicV3 12GB仅低配勉强、推荐24GB+；FlashLips为H100级。**口型同步本地主选MuseTalk 1.5，无二选**。云端H3镜头自带原生对白+口型，该步骤免——口型工作量与引擎路线挂钩。

### 3.4 统筹/执行制片（Line Producer & 1st AD）｜优先级：高（调度枢纽）

| 项 | 定义 |
|---|---|
| 现实原型 | 执行制片 Line Producer + 第一副导演 1st AD + 制片主任（小剧组现实合一配置） |
| 核心职责 | ①**镜头开拍单汇总与派发**（摄影指导产出镜头参数部分→统筹汇总布光方案/参考资产/质检标准/引擎选择→派发全岗位）②handoff调度与进度跟踪（DPR日报告对齐）③**预算扣费执行与引擎调用账本**（budget_manager.py操作者）④岗位就绪清单核查（开拍前交接物到位检查） |
| 工具链 | handoff系统+budget_manager.py+镜头开拍单模板（附录E字段） |
| 交接物 | 镜头开拍单、进度日报、预算账本、延误日志 |
| 边界 | **制片人管决策**（预算上限/验收/拍板），**统筹管执行**（派单/记账/追进度）；艺术总监"按镜头选引擎"是创意决策仍归艺术总监，统筹只执行调用与记账。v3.0开拍单由摄影指导独担，v4.0改为"摄影指导供稿、统筹汇总"——现实剧组1st AD正是此职能 |

## 4. 原岗位边界修订（4处）

| 岗位 | 修订 | 理由 |
|---|---|---|
| **剪辑师** | +字幕/语音转写职责（faster-whisper/SenseVoice生成SRT→成片字幕合成）+成片封装规范（x264/响度/容器） | 现实剧组字幕归后期；转写工具P0就位 |
| **声音设计师** | −BGM生成职责（移交作曲）；+声音分离（UVR5/Demucs）+EBU R128响度规范（ffmpeg-normalize） | 作曲岗拆分的镜像调整；分离/响度工具P1就位 |
| **场记/质检** | +SenseVoice对白核对辅助（台词忠实度检查）；DIT素材管理职能维持不变 | 对白进时间线后的忠实度是新质检维度 |
| **道具师** | **维持独立岗位**（否决调研报告"并入置景"建议） | 理由：①道具一致性靠Ref2VA多参考（≤9图）挂载，与置景的场景级一致性是**两种引擎用法**②《雨夜寻猫》空猫窝/铃铛是叙事锚点道具，穿帮成本高③现实剧组Set Decorator与Props Master本就是两岗。仅收紧边界：道具师只管"单体物件资产"，场景内陈设归置景 |

## 5. Agent底层技术栈升级（MCP / Function Calling / 框架 / Skill）

### 5.1 三层模型（调研定稿的认知框架）

```
Skill层（最高）：定义"做什么"——SOUL.md岗位卡、工作流、团队规范
Tool层（中间）：定义"用什么"——Function Calling/Tool Use（JSON Schema工具定义）
MCP层（底层）：定义"怎么连"——工具发现/授权/传输协议（2026-07-28版已无状态化，Linux Foundation托管）
```

### 5.2 保留什么（自研机制被验证为正确）

| 我们现有 | 业界对应 | 结论 |
|---|---|---|
| SOUL.md岗位卡 | Anthropic Agent Skills（SKILL.md） | 保留核心思想；格式可对齐SKILL.md规范（YAML frontmatter的name/description+scripts/references目录化）——**渐进升级，阶段2执行** |
| handoff交接机制 | OpenAI Agents SDK Handoff / 微软A2A | 保留；MCP/A2A只解决工具与Agent间连接，不覆盖业务交接逻辑 |
| K13版本锁定 | 框架checkpoint | 保留；业务机制无对应替代 |
| 多维表格协作 | 框架状态管理 | 保留 |

### 5.3 吸收什么（3点，按阶段）

1. **SOUL.md格式对齐SKILL.md规范**（阶段2）：YAML frontmatter（name≤64字符/description≤1024字符）+ 岗位资源目录化（scripts/工具脚本、references/规范文档）——不改业务只改包装，提升可维护性
2. **结构化输出全面Pydantic化**（阶段1起）：handoff deliverables与质检报告统一JSON Schema强制输出（ViMax BestImageResponse模式，已在附录D）——岗位间交接从自由文本升级为机器可校验结构
3. **MCP封装工具层**（阶段3再评估）：ffmpeg-mcp、ComfyUI MCP server已有现成生态（MCP官方registry+Claude连接器目录950+）；但**现阶段不迁移**——Hermes bot直接调python脚本已够用，18岗位×工具不多时MCP是过度工程。阶段3工具数量膨胀或接入外部Agent时再引入，且必须白名单防tool poisoning（微软2026安全博客已警示）

### 5.4 不引入什么

- **LangGraph/CrewAI等编排框架**：React Flow节点图+api_server.py已实现同构功能（节点/边/审批/checkpoint对应K13/预览即审批），换框架=重构风险零收益
- **AutoGen/AG2**：已维护模式，新项目不建议首选（业界共识）
- 结论：我们不是"缺框架"，是"缺岗位和工具"——资源投向正确

### 5.5 LLM底座分级选型（拍板项，按成本敏感原则）

| 岗位分级 | 岗位 | 能力要求 | 候选（2026格局） |
|---|---|---|---|
| 决策创作岗 | 制片人/艺术总监/编剧/统筹 | 长上下文+复杂判断+中文 | Claude（工具调用最强，贵）/ GPT级 / DeepSeek V4（性价比） |
| 专业执行岗 | 摄影指导/灯光/分镜/服装/置景/道具/作曲/场记质检 | 结构化输出+领域知识 | DeepSeek V4 / GLM / Qwen（中文+便宜） |
| 技术执行岗 | 动画师/视效师/调色师/声音设计师/剪辑师 | 工具调用可靠+参数准确 | 同上，重tool calling可靠性 |

> 价格按第三方基准参考，具体以官方刊例为准（未验证项不落预算）。建议：**决策岗与执行岗分级配置**，在Hermes config.yaml按bot配不同底座——老板按当期各家实际报价拍板，原则"执行岗性价比优先，决策岗质量优先"。

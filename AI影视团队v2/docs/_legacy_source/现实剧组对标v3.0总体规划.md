## 0. 规划总原则（锁定机制）

1. **先规划后执行**：本文档冻结后，执行阶段只按文档推进，不做方案级改动；任何变更须老板拍板并更新本规划（版本号递增）
2. **现实剧组为标尺**：岗位、交接物、流程全部对标好莱坞工业标准，AI身兼多职但职能不缺位
3. **专业对口原则**：每个环节用该领域专业最强的模型，不为省钱用错工具，也不为炫技用贵工具
4. **本地开源兜底 + 云端API关键镜头**：草稿迭代零现金成本，成片质量由云端引擎保障
5. **实拍感唯一验收标准**：成片观感=现实剧组实拍，PPT感/PPT级廉价效果零容忍

### 1.2 制作流程五阶段

| 阶段 | 核心工作 | 产出物 | 决策点 |
|---|---|---|---|
| 开发Development | 剧本、融资、核心团队 | 剧本定稿 | 项目绿灯 |
| 前期Pre-production | 剧本分解、选角、勘察、预算细化 | Shooting Script、拍摄计划、Call Sheet | 能否开机 |
| 拍摄Production | 按日计划执行+**场记记录** | 素材、场记本、日报告 | 当日是否达标 |
| 后期Post | 剪辑、调色、声音、母版 | 粗剪→成片 | 验收 |
| 发行Distribution | 发行、宣发、版权 | 发行记录 | 市场 |

### 1.3 精简剧组启示（5-15人短剧级）

现实小剧组身兼多职，但**五个职能绝不缺位**：导演、摄影指导、录音、制片/副导、剪辑。→ 我们的Agent架构同理：岗位可合并，职能必须齐全。

### 2.1 与现实剧组对照后的关键差距

| 现实职能 | 我们现状 | 差距结论 |
|---|---|---|
| **场记**（连续性记录+现场质检） | 无专职，靠人工眼检 | **最大缺位**——"五官奇怪/道具穿帮"本应由场记拦截；ViMax"自动一致性检查"正是此职能的AI实现 |
| DIT（素材管理/色彩管理） | K13版本树已实现素材管理 | 已覆盖，并入场记岗（现实小剧组也常由2nd AC兼） |
| 导演（创意总指挥） | 老板+艺术总监分摊 | 维持——老板=导演（最终拍板），艺术总监=执行导演 |
| 服装/妆发 | 角色设计师覆盖 | 已覆盖，character_lock含服装发型连续性 |

| 特技/动作 | 无 | 暂不需要（《雨夜寻猫》无动作戏），后续题材扩展再议 |

### 2.2 最终架构：13→14岗位（+1新增，0删减）

**新增第14岗位：场记/质检（Script Supervisor & QC）**

| 项 | 定义 |
|---|---|
| 核心职责 | ①每镜头生成后**VLM自动一致性检查**（与character_lock/scene_lock/Prop Sheet参考图比对，不过审不进时间线）②维护**场记本**（每镜参数/seed/版本/连续性记录，现实Continuity Script的AI版）③素材管理（DIT职能，版本树守门） |
| 技术方案 | 本地**Qwen3-VL**（12GB可跑，¥0.2/千tokens级别API兜底GPT-4o）+ 规则引擎（自动比对：五官/服装/道具/色调） |
| 解决痛点 | "五官奇怪"进过成片、"道具穿帮"、"镜头间不一致"——**全片质量最后防线** |
| 现实对标 | ViMax开源框架验证过的机制（每图生成后与参考图验证才采用），我们岗位化 |
| 交接物 | 质检报告（过审/退回+原因）、场记本 |

其余13岗位维持v2.0定义不变（灯光/摄影指导/道具/调色/声音设计师等）。

### 2.3 剧组式协作机制升级（交接物制度化）

| 现实机制 | 我们的落地 |
|---|---|
| Call Sheet日通告单 | 每镜生成前由摄影指导产出**镜头通告单**：镜头参数+参考资产+布光方案+质检标准+引擎选择——"开拍"前所有岗位输入到位 |

**关键情报**（2026-09两批深度调研验证，详见《v3.0技术附录-部署与接入手册.md》）：
1. **Wan 3.0登顶**Artificial Analysis视频榜（Elo 1335）且已进ComfyUI原生节点（v0.33.4，30秒单段+20参考资产+指令编辑），但为**API计费未开源**（官方价0.30-1.20元/秒，注册即用+免费额度30秒）——本地兜底仍是Wan 2.2 5B；**全场最低价视频API实为Vidu Q2 540P约0.0875元/秒**
2. **Qwen3-VL-4B本地可跑**（约6GB显存）且ComfyUI已有专用节点包支持2-5图多图比对（similarity/difference分析）——场记岗质检零现金成本，技术上闭环
3. **H3官方发布提示词手册**（GitHub MiniMax-H3 SKILL.md）：镜头描述三字段结构（integrated_multimodal_description时间戳分镜+overall_soundscape+non_diegetic_music）+运镜术语表（Push In/Pan/Tilt/Arc/Tracking/POV）+五模式写法（T2VA/I2VA/FL2VA/L2VA/Ref2VA）——编剧/摄影指导/声音设计师的镜头描述产出直接采用此结构
4. **ViMax一致性检查源码已直读**（best_image_selector.py）：实为"多候选图+VLM评估选最优+理由输出"，并无阈值强制重生成逻辑——我们的场记岗在其基础上增强为"达标注记+不达标定向重生成"，是其未做到的升级
5. **原生音轨已成旗舰标配**（H3双声道/可灵Omni音画同步/Veo 3.1同步音频）——对白口型与环境音从生成端解决；可灵原生4K已商用
6. **5新岗位全部有现成ComfyUI节点**（ICLightApply/WanCameraEmbedding/KontextImageToImage/ComfyUI_Qwen3-VL/RadianceGradeMatch），自研集中在prompt模板与流程编排，无需写新模型节点——开发量可控
7. 4K写实：可灵原生4K已商用，Veo 3.1原生4K——但人物特写仍是全行业短板（我们规避策略：镜头语言设计上多用中远景+侧逆光）

## 4. 混合策略决策表（引擎分层）

| 层 | 用途 | 引擎 | 现金成本 |
|---|---|---|---|
| L0 草稿层 | 剧本迭代/构图试验/内部预览 | 全本地（Flux+Qwen3-VL+Wan2.2+GPT-SoVITS+ACE-Step） | ¥0 |
| L1 成片层 | 全片正稿生成 | 云端主力引擎按镜头调度（Wan 3.0/H3/可灵/Seedance，艺术总监按镜头特性选） | 打样验证后定 |
| L2 增强层 | 关键镜头升级 | 4K引擎（可灵）/ 2K重生成（H3-Regenerate-2K）/ IC-Light重打光 | 按需 |

**按镜头选引擎规则**（对标OiiOii核心策略）：
- 人物特写/对白镜 → H3（原生口型+情绪）或可灵3.0（4K面部肌理）
- 动作/运镜复杂镜 → Wan 3.0（30秒单段连续镜头）或 Seedance 2.5
- 氛围/转场镜 → 本地Wan 2.2（省现金）或 Vidu Q2（约¥0.156/秒）
- 一致性要求高 → H3 Ref2VA（≤9图+3视频参考）或 Wan 3.0 Omni（20参考）

## 6. 实拍感开拍标准（反PPT感Checklist，每镜强制）

> 现实剧组开机前有Call Sheet+各部门确认；我们每镜"开拍"（提交生成）前必须全项通过

| # | 检查项 | 责任岗位 | 不通过则 |
|---|---|---|---|
| 1 | 全镜头视频化，0%静图推拉 | 摄影指导 | 退回分镜 |
| 2 | 运镜写入生成参数（Camera Move/焦段/景别结构化字段） | 摄影指导 | 退回分镜 |
| 3 | 布光方案先行（光比/色温/主光方向入prompt） | 灯光师 | 补布光图 |
| 4 | 角色/场景/道具参考图全部挂载（Ref2VA/Kontext） | 道具师+角色/置景 | 禁止裸生成 |
| 5 | 引擎按镜头特性选定（对白镜≠动作镜） | 艺术总监 | 重新选型 |
| 6 | 生成后VLM一致性检查（五官/服装/道具/色调） | **场记/质检** | 不过审不进时间线 |
| 7 | 镜头间色彩对齐主参考帧 | 调色师 | 回调色 |
| 8 | 对白口型/环境音优先走原生音轨引擎 | 声音设计师 | 标注后期补 |

## 二、网页端·节点图界面（核心交互）

### 设计理念

前端UI采用类似Blender几何节点（Geometry Nodes）的模块化可视化设计：
- 每个角色/任务/元素都是一个**节点**
- 节点之间用**连线**连接（数据流向/依赖关系）
- 节点有多个**输入端口**和**输出端口**
- 可视化的数据流，和ComfyUI、Houdini、Unreal蓝图、Nuke合成节点图同理念

影视/3D行业从业者天然熟悉这种界面。

### 节点类型

| 节点类型 | 视觉 | 输入 | 输出 |
|---------|------|------|------|
| 元素节点 | 矩形，含参数面板 | 上游元素引用 | 元素UUID |
| 任务节点 | 圆角矩形，含角色图标 | 前置依赖任务 | 交付物 |
| 审查节点 | 菱形，含审查项 | 待审交付物 | 通过/打回/附注 |
| 决策节点 | 六边形，含选项 | 待决策事项 | 选择结果 |
| 元事件节点 | 三角形 | 前置事件 | 决议清单 |

### 节点内部结构

每个节点展开后显示：
- **输入端口**（左侧）：接收上游数据，显示来源节点名+UUID
- **参数面板**（中间）：🧠创作意图 + ⚙️具象参数 + 📝干预注释
- **输出端口**（右侧）：输出交付物UUID，可被多个下游节点引用
- **状态指示器**（顶部）：🟢已通过/🟡审查中/🔴阻塞/🔵进行中/⚫未开始
- **版本切换器**（底部）：V1/V2/V3切换，K13不可变版本

### 连线

| 连线类型 | 视觉 | 含义 |
|---------|------|------|
| 实线箭头 | → | 硬依赖：上游必须完成才能启动下游 |
| 虚线箭头 | ⋈ | 软引用：下游引用了上游数据，但不阻塞启动 |
| 红色高亮 | ✗→ | 冲突：两节点参数矛盾，需解决 |
| 绿色脉冲 | ✓→ | 刚确认通过的数据流 |

### 节点图布局

```
[元素:角色_林小雨] ──→ [任务:角色设计] ──→ [审查:Auto-QC] ──→ [审查:艺术总监] ──→ [决策:老板]
                              ↑                      ↑
[元素:场景_雨夜] ──→ [任务:场景设计] ─────────────────┘
                                      ↓
                              [任务:分镜] ──→ [任务:动画] ──→ [审查] ──→ [决策]
```

### 节点图的方案设计映射

| 方案设计 | 节点图呈现 |
|---------|-----------|
| DAG依赖图 | 直接就是节点图——连线=依赖关系 |
| 元素系统 | 每个元素是一个节点，参数写在节点内部 |
| 变更提案（K19） | 从节点A拉一条线到节点B=提议修改B |
| 影响传播推演（#4） | 改一个节点→所有下游连线高亮闪红 |
| 版本树（K13） | 节点底部展开多个版本，点切换=换指针 |
| 审查链路 | 数据从左到右流过Auto-QC→艺术总监→老板各节点 |
| 探索/生产双轨（K7） | 探索模式的分支=从某节点分叉出一条新连线 |
| 叙事连续性检查 | 编剧对照检查清单 + Auto-QC辅助（非独立引擎），冲突节点间红色提示线 |
| 创作债务（K10） | 节点贴"债务"标签，显示逾期风险 |
| 置信度热力图（K3） | 节点按置信度着色：红/黄/绿 |

### 分层渲染（无级缩放）

节点图不是全塞一张图，分三层缩放——类似Google Maps：

| 层级 | 缩放范围 | 看到什么 | 类比 |
|------|---------|---------|------|
| 宏观层 | 缩到最小 | 项目大阶段进度条（剧本完成→角色设计完成→第3镜通过→渲染中） | 全国地图 |
| 中观层 | 正常大小 | 某阶段的节点连线流程（角色设计师→Auto-QC→艺术总监→老板） | 城市地图 |
| 微观层 | 点进去 | 单个节点的详细参数面板（角色名/服装/色调/版本号） | 街道地图 |

**防割裂设计**：
- 缩放过渡时节点平滑展开/折叠，不是跳转
- 上游下游连线始终半透明保留在视野边缘
- 顶部面包屑导航："项目 > 角色设计阶段 > 第2镜 > 角色参数"

### 交互操作

| 操作 | 效果 |
|------|------|
| 点击节点 | 展开参数面板+版本历史 |
| 拖拽连线 | 创建新依赖关系（需制片人/规则层确认） |
| 右键节点 | 重建/回滚/废弃/新建分支 |
| 框选多个节点 | 批量操作（批量通过/批量回滚）+ 渲染一段流程的输出 |
| 缩放 | 宏观→中观→微观，无级缩放，平滑过渡 |
| 搜索 | 按元素名/角色/镜头号搜索节点 |

### 技术选型

节点图前端定案：**React Flow**。
- React生态最成熟、文档最全、社区案例最多
- 自定义节点/连线/小地图/缩放全部内置
- LiteGraph适合ComfyUI那种重参数编辑器，不适合做项目管理界面
- Rete.js灵活性强但开发成本高
- Drawflow太简陋撑不起分层渲染

## 三、网页端·项目地图（状态驱动界面）

### 理念

Kimi K5 + WorkBuddy W1决策：群聊退化为"状态变更通知层"，协作中心是可视化的项目状态机。老板打开的不是群聊，而是一个活的项目地图。

### 界面设计

**项目地图**：每个镜头是一个节点，按DAG依赖关系排列。

| 节点颜色 | 状态 | 含义 |
|---------|------|------|
| 🟢 绿 | 已通过 | 老板已确认 |
| 🟡 黄 | 审查中 | 待Auto-QC或艺术总监审查 |
| 🔴 红 | 阻塞 | 卡住了，需要干预 |
| ⚫ 灰 | 未开始 | 前置依赖未满足 |
| 🔵 蓝 | 进行中 | 角色正在工作 |

点击任意节点展开：
- 当前版本预览
- 所有历史版本
- 决策记录（谁在什么时候做了什么决定）
- 前置依赖状态
- 下游影响清单

**信息密度控制**：
- 默认只显示节点+颜色+镜头编号
- 点击展开详情，不打扰其他节点
- 老板不需要翻消息流，一眼看到全局进度

### 状态变更通知

群聊（或飞书）只推送**状态变更摘要**，不是每条消息都推：
- "镜头3从🟡变为🟢——老板已确认"
- "镜头5从🔵变为🔴——动画生成超时，需干预"

消息量从O(n)降到O(√n)——只有状态变更才推送，角色间的技术沟通不推送。

## 四、网页端·创作工作流（设计→预览→锁定→生成）

### 核心理念

废弃"托管模式/对话模式"二分法，改为Blender式工作流：先设计节点连线，局部预览确认，锁定满意结果，最后整片生成。无需模式切换，无割裂感。

### 两阶段工作流

**阶段一：设计 + 预览**

1. 把节点连好线、调好参数（剧本→角色设计→场景→分镜→动画→音效→剪辑）
2. 任何生成类节点（生图/生视频/配音/BGM）可单独点"渲染"看效果
3. 也可框选多个节点，渲染一段流程的输出
4. 渲染由用户手动触发，不自动实时渲染（AI生成慢，不适合实时）
5. 类似Blender改完节点后手动点渲染看单个节点输出

**阶段二：整片生成**

1. 节点图设计确认OK，所有生成类节点已锁定
2. 点"生成整片"
3. 系统按DAG连线顺序从头跑到尾，输出最终成品

### 生成类节点的锁定机制

**问题**：AI生成像抽卡，每次渲染结果不同。如果不锁定，下游节点每次引用的都会变。

**锁定功能**：
- 用户对某个生成类节点的渲染结果满意 → 点"锁定"
- 锁定后该结果冻结为K13不可变版本
- 下游所有节点引用这个冻结版本，不再引用"最新输出"
- 再点"渲染"会生成新版本，但下游不会跟着变——除非手动切换引用指针

**锁定的连锁效应**：
- 回溯 = 切换锁定指针到旧版本
- 版本树 = 一个节点可锁多个版本V1/V2/V3，哪个锁了哪个是当前引用
- 影响传播 = 改了锁定的版本，下游连线高亮提示"上游变了，你要不要重新渲染"
- **永远不自动更新下游**——锁定就是锁定，改了要手动确认

### 预览即审批

预览本身就是审批流程——渲染单个节点看效果，觉得不行就改参数再渲染，觉得行就锁定往下走。不需要额外的卡片审批按钮。

### 双入口编辑（对话+节点图）

两种编辑方式都可用：
- **对话入口**：在对话框跟AI说"把林小雨的裙子改短一点"，AI改完后节点图上对应节点闪一下
- **节点图入口**：直接点开节点参数面板改

两个入口的规则统一用锁定状态约束：
- 未锁定节点：随便从哪个入口改，都是草稿
- 已锁定节点：不管从哪个入口改，都要走变更提案流程

### 意图驱动（Kimi K1）

老板给出创作意图："这场戏要表现角色内心的撕裂感"→系统自主生成3种截然不同的创作路径：
1. 写实压抑：冷色调+低机位+长镜头
2. 超现实破碎：跳切+扭曲空间+不协调音效
3. 静默留白：大段无声+环境音+单一特写

每种附带"为什么这样表达"的创作阐述。老板做**选择题而非判断题**。

### 预测性预审（Kimi K2）

系统建立老板偏好的隐式模型：
- 不只是"喜欢暖色调"
- 而是"在雨夜场景倾向高对比而非柔和"
- "当角色处于弱势时偏好低机位"

提交预览时直接说："按您过往偏好，预判您会选V2的冷调版本，已预生成。如不符请点修改。"

把"确认"变成"纠偏"，认知负担从老板转移到系统。

### 导演意图文档（Kimi K6）

项目初期老板只拍板三件事：
1. **情绪基调**（如"压抑中带着温情"）
2. **视觉母题**（如"雨水作为时间意象"）
3. **不可逾越的红线**

艺术总监在意图范围内有**审美裁决权**——技术无硬伤且不违背意图文档，可直接拍板。只有两种情况升级老板：
1. 艺术总监判断与意图文档冲突
2. 艺术总监内部无法调和的分歧

老板从"每个镜头的色调法官"变成"项目灵魂的守门人"。

### 老板介入强度档位

| 档位 | 说明 | 适用场景 |
|------|------|---------|
| 严格审查 | 每个镜头确认 | 短片、样片阶段 |
| 抽样审查 | 只抽审关键镜头 | 批量生产系列短视频 |
| 放手模式 | 只终审剧本+最终成片 | 快速概念草稿 |

系统根据档位自动调整预审策略和推送频率。

## 五、网页端·分镜板与时间线

### 分镜板

类似OiiOii的Canvas画布：
- 每个镜头一张卡片，显示预览图+状态
- 可拖拽重排顺序
- 点击进入镜头详情：参数/版本/审查记录/上下游依赖

### 非破坏性编辑

改剧本后下游agent自动重新输出，不影响已确认的镜头：
- 修改镜头3的角色参数 → 只有镜头3和它的下游受影响
- 镜头1、2已确认 → 不动
- 系统自动推演影响范围，老板确认后执行

### 单镜头重建

对某个镜头不满意 → 点"重建" → 系统用最新参数重新生成该镜头，不影响其他镜头。保留旧版本可随时回退。

### 时间线视图

所有镜头按播放时序排列，显示：
- 每个镜头时长
- 总片长累计
- 叙事时间轴（故事世界的时间线）
- 情绪弧光曲线（角色情绪随时间变化）

## 六、网页端·版本树（K13不可变版本）

### 理念

WorkBuddy W2决策：以Kimi K13为唯一版本模型，消灭四套并存。

### 核心设计

- 每个元素每次确认后生成一个**UUID**，永不修改
- 镜头不存储参数，而是存储**元素引用清单**（`角色_女主:uuid_a1b2`、`场景_雨夜:uuid_c3d4`）
- 版本树可视化：树状图展示每个元素的版本演化
- 回溯时零数据迁移——只是换指针

### 版本膨胀管理

项目做下来几百个版本，管理策略：
- **草稿折叠**：未锁定的尝试版本默认收起不显示，只显示锁定的版本
- **废弃归档**：试了5版只锁了1版，剩下4版不删但藏起来，需要时再翻
- **孤儿标记**：没有任何下游引用的版本标"无引用"，提醒"这个版本没人用，要不要删"

### 网页端版本树界面

```
角色_林小雨
├── V1 (uuid_a1b2) — 初始版本 [草稿] （已折叠）
├── V2 (uuid_c3d4) — 修改裙摆 [条件可修改] （已折叠）
└── V3 (uuid_e5f6) — 确认版本 [冻结] ✅
     └── 被镜头3、5引用
```

点击任意版本：
- 查看该版本参数
- 查看与上一版的diff
- 查看哪些镜头引用了它
- 一键回滚（换引用指针，不删数据）

### 可修改性标签（豆包#44）

| 等级 | 含义 | 改动门槛 |
|------|------|---------|
| 高可修改 | 草稿 | 随便改动 |
| 条件可修改 | 部分定稿 | 改动产生连锁代价 |
| 冻结 | 重大里程碑定稿 | 需特殊审批流程 |

### 生成种子快照（豆包#57）

每次生成保存完整输入：prompt、seed、采样参数、参考图索引。独立归档，和元素参数解耦。即使元素库后续修改，仍可复现当初靠什么输入得到对应画面。

## 七、后端·Hermes 9个agent

### 角色清单

| 角色 | 英文 | 职责 | 核心工具（W3：每角色最多2个） |
|------|------|------|---------------------------|
| 制片人 | producer | 总控调度、状态管理、成本监控 | Hermes原生+通知API |
| 艺术总监 | art_director | 审查叙事+审美+意图对齐 | 视觉embedding比对+CLIP |
| 编剧 | screenwriter | 剧本/台词/旁白 | Hermes原生 |
| 角色设计师 | character_designer | 角色设定图 | ComfyUI+Photoshop MCP |

### 变更提案机制（锁定驱动）

变更提案的触发由**锁定状态**决定，不需要额外的探索/生产模式区分：

- **未锁定节点**：随便改，改了就是草稿，不走提案流程。反正还没锁定，不影响下游
- **已锁定节点**：改动走完整提案流程，因为改锁定版本可能影响下游

提案流程：
```
提案ID：#123
目标元素：角色_林小雨（已锁定V2）
提议修改：{裙摆飘动幅度: "high" → "low"}
理由：与雨夜场景氛围冲突
```

系统收到提案后：
- 无冲突字段 → 自动合并写入，生成新版本V3
- 有冲突字段 → 生成diff给制片人裁决
- 涉及下游影响 → 下游连线高亮提示"上游变了，你要不要重新渲染"

把"写入协议"从依赖AI自觉变成系统强制约束。

### 元素来源

1. 参考视频解析
2. 生成创造
3. 网上搜索
4. 资料库
5. 用户上传
6. 沟通共创

### 元素分类

| 类型 | 例子 | 修改方式 |
|------|------|---------|
| 可精确编辑 | 字幕文本、BGM音量、人物数量 | 改了就是改了 |
| 风格化调整 | 色调、氛围、节奏 | 提供2-3个版本选，不承诺精准修改 |
| 强度梯度（#58） | 暴力程度、灯光明暗、情绪渲染 | 0-10强度刻度，梯度采样 |

### 叙事连续性 = 编剧职责 + Auto-QC辅助

不单独建叙事连续性引擎。叙事连续性是编剧的本职工作——剧本写对了，下游画面不会出现跨镜头矛盾。未来Auto-QC实现后，可辅助检查跨镜头的道具状态、情绪过渡等连续性问题，但现阶段不单独建引擎。

## 十、后端·审查链路

### 三层审查（Auto-QC前置，分期实现）

**Auto-QC分期**：
- 一期（信号处理层，技术成熟）：风格漂移检测、色彩一致性、爆音检测、黑帧/花屏检测
- 二期（视觉理解层，待技术成熟）：手指数量、穿模、口型同步——现阶段靠人工审查

```
角色完成工作
→ Auto-QC自动预检（一期：风格/色彩/爆音/黑帧）
  → 不通过 → 自动打回，不占艺术总监注意力
  → 通过 → 进入下一层
→ L3互检（下游角色读上游元素时自动连续性校验）
  → 冲突 → 写入表格备注，通知上游
  → 无冲突 → 进入下一层
→ L2艺术总监（叙事连贯性+审美统一性+意图对齐+二期技术硬伤人工检查）
  → 客观度量辅助：色彩直方图对比、CLIP视觉相似度、节奏密度数据
  → 不通过 → 通知原角色修改（通过网页端通知，非飞书@）
  → 通过但标记关注 → 暂时接受，提醒后续可能回滚
  → 通过 → 进入下一层
→ L1制片人（流程合规：DAG顺序、预算）
  → 异常 → 介入协调
  → 正常 → 提交老板确认
→ L0老板（预览即审批，不额外建审批卡片）
```

审查压力从O(n)降到O(√n)。

### 客观度量辅助（扣子C6）

| 度量维度 | 数据来源 | 用途 |
|---------|---------|------|
| 色彩直方图对比 | OpenCV | 量化"色调不一致" |
| 镜头运动曲线 | 分析推拉摇移频率 | 量化"节奏不对" |
| 节奏密度数据 | 统计镜头时长分布 | 量化"前半段太慢" |
| 视觉embedding相似度 | CLIP模型 | 量化"角色长得不一样" |

### AI生成特有质检（扣子C1）

| 问题 | 解决方案 |
|------|---------|
| 风格漂移 | 视觉embedding比对，低于阈值自动打回 |
| 重绘一致性 | 锁定未修改参数（inpaint局部重绘），修改后自动diff |
| prompt退化 | 每轮自动精简，超阈值强制重构 |
| 素材衰减 | 重绘次数上限（5次），超过强制回到原始概念稿 |

### 善意偏差识别（豆包#39）

检测到违背约束时不直接判定错误，增加判定分支：询问是失误还是刻意破格。标记为刻意破格后写入记录，后续不再告警。

### 意外之喜捕获（Kimi K9）

AI输出偏离指令但呈现有趣特质时，自动标记"Serendipity"，附偏离度分析和采纳建议。老板可一键"将这个意外采纳为新方向"。

## 十三、成本控制（预算驱动）

### 核心理念

不预测要花多少钱（AI生成成本难预估），改为**预算驱动**——用户提前设上限，快超了提醒，超了自动停。像手机流量套餐。

### 预算驱动机制

| 机制 | 说明 |
|------|------|
| 每镜头硬预算上限 | 用户提前设"这个镜头最多花5块钱" |
| 80%预警 | 花到4块时提醒"已花4元，还剩1元" |
| 100%熔断 | 超预算自动停止该镜头的生成 |
| 实时成本面板 | 老板可随时查看已花费/剩余预算，按镜头粒度展开 |
| 探索分支独立预算 | 实验分支有独立小额预算，花完自动停止 |

### 三类资源约束池（豆包#14）

| 约束 | 预警机制 |
|------|---------|
| 💰金钱预算 | 80%预警，100%熔断 |
| ⏱成片总时长 | 每新增镜头自动累计，超限预警 |
| 📅交付截止时间 | 预推演各环节耗时，预测是否赶得上 |

## 十七、MVP最小闭环（WorkBuddy W6）

### 理念

MVP验证的是"一条流水线能否跑通"，不是"权限体系是否完备"。

### MVP范围

| 项目 | 内容 |
|------|------|
| 角色 | 1个（制片人） |
| 镜头 | 1个 |
| 生成工具 | 1个（ComfyUI） |
| 决策闭环 | 预览即审批（渲染→满意→锁定→往下走） |
| 通知 | 浏览器通知（飞书踢出MVP，MVP期间你就在电脑前） |

### MVP启动前置条件

| 前置项 | 状态 | 阻塞MVP？ |
|--------|------|-----------|
| ComfyUI本体部署（GPU版） | ❌ 未装（torch wheel已下载备好） | 是 |
| ComfyUI MCP连通验证 | 未验证 | 是 |
| 网页端前端骨架（React Flow） | 未开始 | 是 |
| Hermes后端 | ✅ 已有 | 否 |

> ComfyUI部署是关键路径第一块砖——它不装好，MVP的"生成工具1个"就是空中楼阁。开发顺序：ComfyUI部署第一，网页端骨架（React Flow）并行。

### MVP必须包含的三个前置设计

1. **导演意图文档** — 开拍前先写"这部片子要表达什么"，所有角色创作时参考它，防止AI各自理解跑偏
2. **创作债务记录** — 哪些地方"先这样吧以后再改"，记下来，防止做着做着忘了还欠着债
3. **置信度标注** — AI生成的东西自己标"我有几成把握"：红=不确定，黄=还行，绿=有信心。帮你知道哪些地方需要重点看

### MVP验证通过后再加

1. **飞书完整移动端适配**（MVP踢出，验证通过后第一个加回来）
2. 第2-9个角色
3. DAG依赖调度
4. Auto-QC自动化质检（一期：风格/色彩/爆音/黑帧）
5. K13版本树完整管理（草稿折叠/废弃归档/孤儿标记）
6. 变更提案机制
7. 生成种子快照（保留设计，后期实现）

## 1. 团队架构重组结论（9 → 13岗位）

设计逻辑：**把"实拍感"拆解为岗位职责**——光影、运镜、道具、调色正是现实剧组的核心工种，也是我们当前成片最弱的四环。重组方式：拆分（场景设计师、动画师）、合并（音效）、新增（4岗位）、无整岗删减（动画师职责缩水）。

| # | 岗位 | 重组方式 | 核心职责 | 解决痛点 |
|---|------|---------|---------|---------|
| 1 | 制片人 | 保留 | 预算/进度/现金API账户管理 | — |
| 2 | 编剧 | 保留 | 剧本/对白 | — |
| 3 | 艺术总监 | 保留+扩权 | 风格/审美/审核/**按镜头选引擎**（对标OiiOii） | — |
| 4 | 角色设计师 | 保留 | 定调图/三视图/角色一致性 | 五官跑形 |
| 5 | 置景设计师 | 场景设计师更名聚焦 | 场景环境资产/氛围/天气时段 | — |
| 6 | **道具师** | **新增**（拆自场景设计） | 道具资产表（Prop Sheet）/关键道具跨镜头连贯 | 道具穿帮 |
| 7 | **灯光师** | **新增**（拆自场景+动画） | 布光方案/光比/光影prompt/重打光 | 光影平淡=假 |
| 8 | **摄影指导** | **新增**（拆自动画师） | 运镜设计/焦段光圈/首帧锚点构图/镜头语言结构化参数 | **PPT感根源** |
| 9 | 分镜师 | 保留（与摄影指导协作） | 分镜表/时长节奏 | — |
| 10 | 动画师 | 精简为执行岗 | 视频生成执行/多引擎调用 | — |
| 11 | 声音设计师 | 音效工程师合并扩权 | 对白TTS/SFX/BGM/混音全链 | 音频塑料感 |

**协作机制不变**：handoff交接 + K13版本树 + character_lock/scene_lock资产 + 预算熔断，新岗位沿用现有基础设施。

## 2. 四新岗位技术配置（调研结论）

### 2.1 灯光师

| 技术 | 方案 | 本地12GB | 成本 | 集成 |
|---|---|---|---|---|
| 生成端光影控制 | Wan2.2 Film Aesthetics Control System（自然语言控制照明/色彩/构图）+ SDXL/Flux 光照prompt体系（rim lighting/volumetric/hard sunlight/soft directional） | ✅ 已部署 | 免费 | 现有管道 |
| AI重打光 | IC-Light（lllyasviel开源）：对已有画面重算光影 | 轻量可试跑 | 免费开源 | ComfyUI节点 |
| 电影级环境光合成 | Beeble SwitchX（ComfyUI Partner Node） | ❌ 云端 | 720p约30 credits/30帧 | ComfyUI Partner Node |

**工作流**：剧本阶段定布光方案（夜景外景光比/主光方向/色温）→ 分镜阶段输出光影关键词+光比参考 → 生成阶段注入prompt → 成片阶段必要时IC-Light局部重打光。

### 2.2 摄影指导

| 能力 | 技术方案 | 说明 |
|---|---|---|
| 焦段/景深模拟 | Flux.1 dev 焦段prompt（85mm f/1.4特写/24mm广角/35mm自然/anamorphic bokeh） | 首帧锚点图的镜头语言来源 |
| 运镜指令 | 可灵3.0（pan/tilt/zoom/roll/trajectory轨迹）、Seedance 2.5（dolly/pan/track/orbit）、Veo 3.1（tracking shot/low-angle） | 云端引擎运镜写入生成阶段 |
| 结构化参数体系 | 借鉴Higgsfield Cinema Studio双层设计：**项目级**（Genre/Style/Lighting/ColorPalette）+ **镜头级**（Camera/Lens/Focal/Aperture，Lens含Anamorphic/Warm Halation/Vintage Haze） | 平台数据结构直接照此建字段 |

**工作流**：分镜阶段输出镜头参数表（Camera/Lens/Aperture/Camera Move）→ 首帧锚点图按焦段生成 → 视频生成按运镜指令提交。

### 2.3 道具师

| 技术 | 方案 | 用途 |
|---|---|---|
| 多图参考一致性 | H3 Ref2VA（≤9图+3视频+3音频，≤12文件）：图1负责身份服装、图2负责道具外形分工注入 | 跨镜头道具锁定 |
| 道具图编辑 | Seedream 4.5（多图参考/编辑一致性，约0.25-0.5元/张） | 道具资产图迭代 |
| 资产管理 | Prop Sheet（对标LTX Elements）：剧本阶段提取道具清单→名称/材质/颜色/尺寸/出现镜头/参考图 | 《雨夜寻猫》关键道具：猫窝、猫粮袋、寻猫启事、手机手电 |

### 2.4 调色师

| 技术 | 方案 | 说明 |
|---|---|---|
| 主流程 | Colourlab AI 4（DaVinci Resolve OFX插件：Balance/Match/Film Emulation，Public Beta免费）+ 统一Look LUT | 多引擎镜头色彩对齐到主参考帧 |
| 生成端 | Wan2.2/Flux prompt控制色调方向（teal-and-orange/film grain） | 生成时就统一基调 |
| 开源备选 | OpenColorIO + Resolve LUT 流程 | 零依赖方案 |

### 2.5 四岗位协同工作流（插入点）

```text
剧本阶段 → 四岗位共同参与：灯光（光比/色温）·摄影（镜头语言体系）·道具（Prop Sheet提取）·调色（全局Look/LUT定义）
分镜阶段 → 交接物：光影关键词+光比参考 / 镜头参数表 / 道具参考图+一致性锚点 / 全局LUT+参考帧
生成阶段 → 镜头为生产单元：本地Flux首帧锚点（摄影指导规格）+H3 Ref2VA锁一致性+云端引擎执行运镜
成片阶段 → 调色师统一收口：批量套LUT+镜头间Match+最终交付
```

### 2.6 旧岗位技术升级要点（简要）

- 角色设计师：SDXL → **Flux.1 dev FP8**（写实明显升级，三视图流程沿用three_view_client策略）
- 置景设计师：scene_lock沿用 + Wan2.2氛围控制
- 动画师：本地Wan2.2 5B兜底 + 云端H3/可灵/Seedance按镜头调度（引擎接入层待开发）
- 声音设计师：edge-tts → **GPT-SoVITS（本地克隆）/豆包语音（云端）**；程序合成BGM → **ACE-Step v1.5（MIT开源，<4GB显存）**；H3原生音轨承接环境音
- 艺术总监：新增"按镜头选渲染后端"职责（对标OiiOii核心策略）

## 3. 竞品深度情报（官方文档级）

### 3.1 OiiOii 内部机制（深挖结果）

1. **7 Agent共享Scene Graph**：编剧把idea解析成结构化Scene Graph，下游所有Agent共享同一份数据——这是跨环节一致性的根基
2. **Art Director按镜头选渲染后端**：25+模型池（Sora 2/Veo 3.1/Seedance 2.0/2.6/Kling/Hailuo 02/Vidu/Midjourney/Seedream/Nano Banana），同一项目里角色镜头用Seedream、动作镜头用Sora 2、转场用Kling——**对抗单模型工具的核心策略**
3. **角色一致性引擎**：Character Designer锁定面部结构/服装/比例/配饰，生成多角度设定图（正/侧/背/3/4）持久化传递给每个下游镜头（与我们的character_lock+三视图思路同构，验证方向正确）
4. **Canvas=并发生成+联动编辑**：并发批量生成；改一元素相关场景自动同步；首尾帧参考；Universal Reference任意图做风格/内容引导
5. **双模式**：Story Films（托管，输入idea全自动管线）vs Canvas（工作模式，逐步控制每镜头）
6. **经营现状**：Pre-A+轮数千万人民币（春华资本等）；与火山引擎签年度协议需2026年底前支付5000万买Seedance API（现金流压力）——侧面印证引擎成本是大平台也头疼的问题

### 3.2 VideoClaw（与我们架构最像的竞品）

- 4 Agent：Router（输入分类）/Planner（结构化分镜）/Writer（剧本+prompts）/Director（输出前一致性审查）
- 6类节点：项目大纲/角色资产/场景资产/剧集脚本/分镜图/渲染视频片段，全部可拖拽、可编辑、可重生
- 引擎：Sora 2、Veo 3.1 Fast、Grok Video（720p/6-15秒）+ Nano Banana出图
- Story Bible=显式节点（项目大纲+角色+场景资产节点化）
- **启示：我们的React Flow节点图方向被商业产品验证；可对照补节点类型**

### 3.3 ViMax 开源框架（港大HKUDS，可直接参考源码）

- MIT协议，GitHub 3500+ stars
- 5 Agent：Screenwriter/Storyboard/Character Designer/Director（**多机位拍摄模拟**）/Producer（编排+质量检查）
- 架构亮点：RAG脚本引擎（长文本保情节）；智能参考图选择（每个新镜头从之前时间线自动选参考）；**自动一致性检查（每张图生成后与参考图验证后才用）**——这个机制值得直接抄进我们的流水线
- 后端：Gemini 2.5 Flash + Imagen + Veo（可换MiniMax）
- 三模式：Idea2Video/Script2Video/Novel2Video

### 3.4 2026新竞品动态

| 竞品 | 动态 |
|---|---|
| **Flova** | 2026年7月8000万美元天使轮；Agent对话驱动+Story Board面板混合交互；支持CLI认证让外部Agent操作 |
| 八点八AniShort | 一站式AI动漫，制作成本降85% |
| 炫佳科技 | AI短剧工业化：40人45天→1-3人 |
| SkyProduction天工 | 昆仑万维AI短剧生产工具 |
| 赛道融资（2026.7） | 可灵30亿美元（估值180亿）、生数5亿、爱诗数亿、智象15亿、Flova 8000万美元，**总超262亿人民币** |

### 3.5 最值得抄的3个发现

1. **按镜头选择渲染后端**（OiiOii）——艺术总监扩权+引擎接入层，已在规划P0
2. **节点化Story Bible**（VideoClaw）——角色/场景/道具做成显式资产节点可连线到镜头（道具师Prop Sheet正好补齐第三类资产）
3. **自动一致性检查**（ViMax开源）——每镜头生成后自动与参考图验证，不过审不进时间线；零成本抄进流水线

### 4.4 能力边界（诚实清单）

**能做到**：原生音频、110分钟AI长片、AI漫剧规模化（50-150元/分钟）、参考图一致性、海外付费意愿成立。
**仍做不到/做不好**：长叙事跨场景角色一致、对白口型与情绪表演、4K写实人物稳定、复杂动作戏/群演、导演级反复调整可控性、原创叙事仍需人主导。

### 4.5 行业对Agent编排方向的判断

**主流结论：Agent编排不是伪需求，是"工具层→平台层"的升级。**
- a16z投资Glif定位"creative super agent"（类比Claude Code for creative work）；a16z专文判断"未来视频都需要Agent协调多模型"
- Poolday："视频模型是基础设施，多Agent系统是产品"
- 商业验证：OiiOii/LTX/Higgsfield全部从单模型工具走向多Agent平台
- **我们的9→13 Agent架构与行业共识方向完全一致**

### 4.6 我们的诚实定位

1. **架构方向**：多Agent编排+节点图画布——与行业头部（OiiOii/VideoClaw/ViMax/学术CineAGI等）同向，且ViMax开源可零成本参考
2. **成本水位**：《雨夜寻猫》80秒约60-120元，与行业AI漫剧成本（50-150元/分钟）同一量级——不落后
3. **硬件短板**：行业头部用云端旗舰引擎+百万美元算力；我们单卡12GB本地+便宜API兜底，写实上限依赖云端引擎接入（阶段0打样验证）
4. **最大差距**：不是流程（我们13岗位+handoff+版本树比多数竞品细），而是**云端引擎接入层尚未建成**——这正是规划中的P0
5. **独有优势**：本地开源全栈（ComfyUI+Flux+Wan2.2+ACE-Step+GPT-SoVITS）让我们在零现金成本下保持迭代速度，行业平台做不到

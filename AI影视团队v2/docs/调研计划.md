## 2. 老板追加的三条硬要求（写进验收标准）

### 2.1 第 8 条 —— **决策建议明确**

调研**不是罗列信息**。每条结论必须落到**四选一**：

| 标记 | 含义 | 必须给出 |
|---|---|---|
| ✅ **选** | 建议采用 | 理由 + 适用条件 |
| ❌ **不选** | 建议排除 | 理由 + 替代方案 |
| ⚠️ **条件选** | 有条件采用 | **"什么条件下选 / 什么条件下不选"** 的明确判据 |
| ❓ **数据不足** | 无法判定 | **还缺什么数据**才能判 |

**每条模块结尾必须有一张「决策建议汇总表」**，格式：

| 候选 | 写实能力 | 结构控制 | 12GB 可行性 | 成本 | 许可 | 成熟度 | 风险 | **建议** |
|---|---|---|---|---|---|---|---|---|
| … | 1-5 | 1-5 | 跑通/跑不通/未测 | 元/秒或元/条 | 🟢🟡🔴 | 高/中/低 | 高/中/低 | ✅/❌/⚠️/❓ |

### 2.2 第 9 条 —— **反方证据**

**主动找"唱反调"的资料**，避免只收集支持性证据。必须搜的渠道：

| 渠道 | 具体搜法 |
|---|---|
| 开源仓库 issue 区 | 搜 `fail` / `broken` / `oom` / `vram` / `drift` / `flicker` / `inconsistent` / `worst` |
| 社区吐槽 | Reddit / 知乎 / V2EX / 即刻 / B站评论区 / Discord 的真实用户吐槽 |
| **迁移失败 / 弃用案例** | 例：Sora 2 API 已停服、Vidu 腾讯云路径下线 —— **同类"承诺过但没兑现"的案例要专门找** |
| 论文的 limitation / negative result | 论文里作者自己承认的失败场景 |
| 官方文档的"注意事项 / 限制"章节 | 官方自己写的限制往往最诚实 |
| 付费用户的退订/退款讨论 | 说明实际交付与宣传的落差 |

**交付格式**：每条主结论后面必须跟一行 **「反方证据」**——找不到反方证据的，写"**未找到反方证据（已搜 X/Y/Z 渠道）**"，**不许留空**。

### 2.3 第 10 条 —— **术语与口径统一**

不同来源的数字口径不一样，直接比会误判。**先定义，再调研。**

#### 2.3.1 口径统一定义表（本项目唯一算法）

| 术语 | 统一口径 | 禁止的比法 |
|---|---|---|
| **成本·按像素计价** | `成本($) = 单价($/MP) × 宽 × 高 × 帧数 ÷ 1,000,000`，**上行取整**（fal 口径）。与"按秒"口径**必须换算后才能比** | 拿 $/MP 直接和 元/秒 比 |
| **成本·按秒计价** | `成本(元) = 单价(元/秒) × **输出**秒数`；**输入是否计费必须单独注明** | 不注明输入计费就报单价 |
| **成本·积分/credits** | 必须同时给出 `credits × 官方充值档单价(元/credit)`。**禁止用"积分"横向比较** | 旧项目教训：账本用"点数"，报不出真实现金 |
| **成本·单镜实付** | `= 生成次数 × 单次成本 + 失败重试的计费部分`；**失败是否计费必须单独标注** | 只算成功一次的"理想成本" |
| **成本·全片预估** | `= Σ单镜实付 × (1 + 废片率)`；废片率取行业基线 60–80% 或实测值 | 用"一次就成"估算 |
| **性能·吞吐** | 必须同时给：`分辨率 / 帧数 / 端到端秒数 / 峰值显存MiB / GPU利用率% / **是否含模型加载**` | 只报"能跑" |
| **性能·可跑性** | 三态：`跑通 / 跑不通 / 未测`。**禁止"预计能成""应该可以"** | 老板硬约束 |
| **许可·商用** | 三态：🟢可商用 / 🟡有条件（**写明条件原文**） / 🔴非商用。**必须给条款原文 + 出处 URL + 访问日期** | 只写"可商用" |
| **许可·范围** | **权重许可与代码许可必须分开标**（例：Stability Audio 主干 Apache 2.0、SXL 变体非商用） | 混为一谈 |
| **一致性·人脸** | ArcFace 余弦相似度（阈值 ≥0.75），**注明所用模型与数据集** | 用"看起来像" |
| **一致性·真动** | 背景光流中位速 px/帧（阈值 ≥2） | 用"感觉在动" |
| **证据等级** | 一手（官方页 / 官方 API / 官方仓库）／二手（媒体 / 博客 / 论坛）／**未能验证（写明原因）** | 把二手当一手 |

#### 2.3.2 数字必须带上下文

任何数字后面必须跟 **`(来源 + 访问日期 + 证据等级)`**，例如：
`768p 约 0.5 元/秒（MiniMax 官方定价页，2026-09-27 访问，一手）`。

## 4. 验收标准（"调研做全"怎么算）

- [ ] 四个板块全部产出，无缺项
- [ ] 竞品 **20 家**（四类：直接对标 / 已开源 / 商业平台 / 引擎与获奖团队），其中**已开源的读到源码级**
- [ ] 每个关键结论都有**一手**出处；二手必须标注
- [ ] **每条主结论都有"反方证据"一行**（找不到也要写"未找到 + 已搜渠道"）
- [ ] 每条模块有**决策建议汇总表**，且每条都落在 ✅/❌/⚠️/❓
- [ ] 所有数字带 `(来源 + 访问日期 + 证据等级)`
- [ ] 口径统一表（§2.3.1）**在实际写作中被遵守**（抽查 5 处数字可复算）
- [ ] **Blender 侧技术调研**有独立章节（低模库/绑定/动作/depth-normal/MCP 边界）
- [ ] 全文**无**"预计能成""应该可以"类推断

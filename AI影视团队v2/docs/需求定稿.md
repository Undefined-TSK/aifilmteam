## 1. 项目目标（三层，从近到远）

| 层 | 目标 | 老板原话/依据 | 完成标志 |
|---|---|---|---|
| **L1 技术验证** | 证明「Blender 白模 → 大模型写实化」这条链路**在本机跑得通** | 「两个都做，先技术镜后成片」 | 一个 5–10 秒单镜，白模进、写实出，五项硬指标有数值报告 |
| **L2 能力样片** | 用这条件产出一部**像真人剧组实拍**的片 | 「用 AI 做出像好莱坞真人专业团队拍摄出来的影片」 | 《雨夜寻猫》30–45 秒，L1 交付档规格 + 五项硬指标全过 |
| **L3 平台内核** | 把 L1/L2 跑出来的能力**沉淀成可平台化的内核** | 「以平台为目标 + 我们的特色（Blender 加持、输入输出多模态模型、skill、mcp……不限于这些，可扩展）」 | 一套可复用的内核：模型矩阵 + 编排 + 质检 + 账本 + 接口；**形态留后定** |

**平台定位（老板已拍）**：**先做内核，形态后定。**
→ 不做多租户、不做计费、不做开放注册。但**接口按可平台化设计**，第一次对外时不用重写。

## 2. 我们的特色（必须体现在架构里，不能只是口号）

老板点名的四项 + 可扩展：

| # | 特色 | 落地要求（写进架构契约） |
|---|---|---|
| 1 | **Blender 加持** | 白模层不是"辅助"，是**核心确定性来源**：相机/灯光/动作/道具状态/天气/时间轴全在 Blender 定死并渲染。Blender 工程是**可交付资产**（别人能拿去改），不是中间产物 |

## 5. 多模态第一版边界 —— 分层建议（**唯一待拍项**）

老板要求「你给分层建议」。我按 **必备 / 应做 / 可选** 三层排，请老板拍第一版切在哪一刀。

### 5.1 必备（第一版内核必须有）

| 方向 | 模态 | 具体形态 | 为什么必备 |
|---|---|---|---|
| **输入** | 文本 | 一句话创意 / 剧本 / 镜头规格 JSON | 链路起点 |
| **输入** | 图像 | 角色三视图 / 场景锚点 / 分镜图 / **首帧锚定图** | 首帧锚定是治「五官奇怪」的唯一手段 |
| **输入** | 视频 | **Blender 白模粗片**（核心控制输入） | 本路线的心脏 |
| **输入** | 音频 | 对白文本（→ TTS） | 有对白才有口型和情绪 |
| **输出** | 视频 | 逐镜写实化素材 + 成片 | 主产物 |
| **输出** | 音频 | 对白 / 环境 / SFX / BGM + **分轨 stems** | L1 硬指标⑤ |
| **输出** | 结构化数据 | 剧本 / 分镜 / 镜头规格 / 时间线 / 质检报告 / 成本账本 | 平台内核的燃料；也是确权证据链 |
| **输出** | 图像 | 锚点图 / 三视图 / 分镜图 | 资产沉淀 |

### 5.2 应做（第一版跑通后紧接着）

| 方向 | 模态 | 具体形态 | 价值 |
|---|---|---|---|
| 控制输入 | 深度图 / 法线图 / 姿态图 | 从 Blender 导出，作为引擎的**结构化控制条件** | 比"纯视频条件"更强的结构锁定 |
| 控制输入 | 相机轨迹 / 焦段曲线 | 结构化参数喂给引擎 | 运镜可控 |
| 输入 | 3D 工程 | 外部 `.blend` / `.glb` / `.fbx` 白模导入 | 别人能带自己的场景进来 |
| 输出 | 3D 工程 | 我们的 `.blend` 白模工程**作为可交付资产** | "Blender 加持"的体现；别人拿去改 |
| 输入 | 音频 | 参考音色（少样本克隆）/ 参考音乐 | 音色一致性与版权自控 |
| 输出 | 多语言 | 译制版（多语言对白 + 字幕） | 出海承制需要 |

### 5.3 可选（平台化阶段再上）

| 方向 | 模态 | 形态 |
|---|---|---|
| 输入 | 语音指令流 / 多轮对话 | 对话式改镜（"把第 3 秒的灯调暖"） |
| 输出 | 3D 模型 | 从图/视频反推 3D 资产 |
| 输出 | 宣发物料 | 海报 / 预告片 / 竖屏切片 |
| 能力 | 风格库 | 可保存/复用/分享的风格包（对标 OiiOii 的 150+ 风格库） |
| 能力 | MCP server | 把上述能力暴露给外部 Agent 调用 |

### 5.4 老板拍板结论（2026-09-27 16:51）

> **老板答复：全都要。**
> → 第一版多模态范围 = **必备 + 应做 + 可选 三层全做**。

**因此本项要求写进架构契约的内容：**

| 层 | 必须实现的 I/O |
|---|---|
| 输入 | 文本 / 图像（含首帧锚定图）/ 视频（Blender 白模粗片 + 参考视频）/ 音频（对白文本 + 参考音色 + 参考音乐）/ 3D 工程（`.blend`/`.glb`/`.fbx` 导入）/ 语音指令与多轮对话 / 深度图·法线图·姿态图·相机轨迹等控制条件 |
| 输出 | 视频 / 图像 / 音频（含分轨 stems + 多语言译制）/ **3D 工程（我们的 `.blend` 可交付）** / 3D 模型（图·视频反推）/ 结构化数据（剧本·分镜·镜头规格·时间线·质检报告·成本账本）/ 宣发物料（海报·预告片·竖屏切片） |
| 能力 | 风格库（可保存/复用/分享）/ **MCP server（对外暴露给其它 Agent 调用）** |

**派生约束（写进 R3 架构契约）**：
1. **I/O 必须走统一的"模态适配层"**——加模态不改编排层（老板要的"可扩展"落点就在这里）。
2. **分三期实现，但一次设计到位**：必备项先跑通（R4/R5），应做项随内核补，可选项在平台化阶段上。**接口先留全，实现可后补。**
3. **3D 工程作为一等公民的输入/输出**——这是"Blender 加持"作为差异化的落点。
4. **MCP server 从 R3 就按"要对外暴露"设计**接口（副作用操作必须带 handle + 幂等键），不是等平台化阶段再补。

> 以上为**最终定稿**。多模态边界不再有待拍项。

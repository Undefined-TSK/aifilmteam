### 字段与口径定义

- **字段**：`编号｜判据｜工具/命令｜不过怎么办｜出处｜证据等级｜硬度`
- **证据等级（只此三选一）**：
  - `一手` = 官方页面 / 官方 API schema / 官方仓库 / 官方文档 / 官方博客
  - `二手` = 媒体 / 博客 / 论坛 / 第三方评测
  - `未验证` = 无任何来源可引（并在判据中写明原因）
- **硬度（只此两选一）**：`硬门` = 未通过即阻断，不得进入下一阶段；`警告` = 记录并复核，不阻断。
- **自定项**：判据含**本团队自订的字段清单 / 格式与通道规格 / 命名 / 数值阈值 / 白名单 / 限制**、且该部分无法从外部来源推出者，在「出处」栏注明 `本团队自订`，并计入仪表盘"自定项"。标注规则：①判据"一部分有外部出处、一部分为本团队自订"→「证据等级」栏标 `<外部等级> + 自定`（形如 `一手 + 自定` / `二手 + 自定` / `未验证 + 自定`）；②判据完全无外部来源 →「证据等级」栏标 `自定`。判定标准："该具体取值是否能从外部来源直接推出"——能推出（如 VFX 通行的位深惯例）不计自定；只能由本团队选定（如"须含哪些通道""须留档哪些字段"）计入自定。

## A. 白模产出前（Blender 阶段）

| 编号 | 判据 | 工具/命令 | 不过怎么办 | 出处 | 证据等级 | 硬度 |
|---|---|---|---|---|---|---|
| A-01 | 白模宽高比 **必须等于**目标成片宽高比，且在 Blender 阶段定死、一旦确定不得更改。官方原文：`Output size follows the source video, capped to the stable IC-LoRA budget` → 输出尺寸跟随源视频，宽高比同时决定单价与可用时长 | Blender：场景相机 `sensor_fit` / 渲染分辨率锁定；输出后 `ffprobe` 复核 | 回到 Blender 改画幅并**重渲整镜**；不得靠后期裁切（裁切不改变已计费/已生成的输出比例） | fal API schema，`resolution` 字段 | 一手 | **硬门** |
| A-02 | 白模视频的 fps 必须与拟定输出 fps 一致（默认 **24**）。若将做 fps 实验，须整镜同时改、不得只改一端 | `ffprobe -v error -select_streams v:0 -show_entries stream=r_frame_rate,avg_frame_rate` | 重渲白模视频使其与输出 fps 对齐；不一致的素材作废 | fal API schema（`frames_per_second` 默认 24） | 一手 | **硬门** |
| A-03 | 导出**双轨**：轨A = clay RGB 视频（供云端点消费）；轨B = OpenEXR MultiLayer，含 Z + Normal pass | Blender：`View Layer Properties → Passes → Data` 勾 `Z`/`Normal`；`Output Properties → File Format = OpenEXR MultiLayer` | 缺轨B 则该镜**无法接入**任何 depth 条件化后端；补齐后再进入 B 段 | Blender 官方行为（MultiLayer EXR 自动包含全部已启用 pass）+ 本团队自订（"双轨"结构与本项目采用的通道集 {Z, Normal}：Normal 非任何后端所必需，属本项目自选） | 一手 + 自定 | **硬门** |
| A-04 | 轨B 规格：depth/vector 用 **32-bit full float**，压缩 **ZIP（无损）**。**严禁**把 depth 压成 8-bit 视频 | Blender Output 色彩深度设 `Float (Full)`；导出后抽帧检查位深 | 位深不达标的 pass 序列作废重渲 | Blender/VFX 通行做法（多层 EXR 用于合成） | 二手 | **硬门** |
| A-05 | 轨A 与轨B **逐帧严格对齐**：同一相机、同一帧范围、同一分辨率、同一 fps。错一帧即后端无法配对 | 逐帧比对帧号与文件名序列；`diff` 文件清单 | 以轨A 帧清单为准重渲轨B | 本团队自订 | 自定 | **硬门** |
| A-06 | 每镜输出相机元数据 sidecar JSON：`lens` / `sensor_width` / `sensor_fit` / `matrix_world`（逐帧）+ 内参 K。**官方无"一键导出内参"功能，需自写脚本** | 自写 `bpy` 脚本，按帧导出相机参数 | 缺内参则后续无法做几何一致性回归与多后端对齐；本项须**提前排期**，非顺手可得 | Blender 官方无此功能（**缺失性证据：只证明工具不存在，不构成"该导出哪些字段"的依据**）；EXR header 可嵌 metadata 为替代路径；**其余为本团队自订（sidecar 字段清单）** | **未验证 + 自定** | **硬门** |
| A-07 | 全部动画插值统一 **LINEAR**（关掉 Blender 默认 Bezier 的 ease-in/out）；真抛物线用物理仿真而非曲线近似 | `Edit → Preferences → Animation → F-Curves → Default Interpolation = Linear`；已有曲线选中按 `T` 选 Linear；脚本 `bpy.ops.graph.interpolation_type(type='LINEAR')` | 含 ease-in/out 的运动会给模型"非匀速"的运动信号，须重 Key 后再导 | Blender API 文档：`LINEAR` = "straight-line interpolation ... **no ease in/out**" | 一手 | **硬门** |
| A-08 | 脚本创建/写入动画曲线必须走 `action_ensure_channelbag_for_slot(action, slot)`，并**显式绑定** `obj.animation_data.action_slot` | `bpy_extras.anim_utils.action_ensure_channelbag_for_slot`（5.1+） | 不绑 slot → 动画**静默不播**（无报错）；`action.fcurves` 在 5.0 已被移除，用旧 API 直接抛 `AttributeError` | Blender 4.4 slotted actions 升级文档；`action.fcurves` 5.0 移除 | 一手 | **硬门** |
| A-09 | 本机 Blender **无 FFmpeg 编码器** → 一律输出 PNG 序列，再由外部 ffmpeg 合成 | Blender 输出格式设 `PNG`；外部 `ffmpeg` 合成 H.264 | 试图用 Blender 内置编码器会失败/无可用枚举，浪费一轮渲染 | 本机实测（Blender 5.2.2 无可用 FFmpeg 输出枚举）；第三方实测亦记录同一现象 | 一手 | **硬门** |
| A-10 | 人体白模保留头型/颈部等**基础量感**，不做球头。白模越简，模型自由解释空间越大 → 易发生"道具退回占位形状""角色身份漂移" | 白模预览目视检查；对照分镜表逐一确认角色可辨识（靠颜色/高矮/位置锁死身份） | 头部过于简化时补基础量感或加参考图（加图会引入 B-02 门禁） | 即梦白模实测排障表（五个翻车现场） | 二手 | 警告 |

## B. 提交引擎前（参数与配置）

| 编号 | 判据 | 工具/命令 | 不过怎么办 | 出处 | 证据等级 | 硬度 |
|---|---|---|---|---|---|---|
| B-01 | ⭐**基线配置 = 不传 `image_url`**。官方原文：`image_url` 为可选、仅作 **frame 0** 锚，`leave empty to let the render alone drive the result`。不传时**只有 1 个输入**，"宽高比多数投票陷阱"**根本不存在** | 调用时省略 `image_url` | 无（这是最省事基线）；若误传而未做 B-02，可能导致输出比例被改写，须整镜重生成 | fal API schema，`image_url` 字段 | 一手 | **硬门** |
| B-02 | **仅在启用参考图增强时生效**：所有参考图的宽高比必须裁成 **clay AR**，保证 clay AR 在全部输入中**占多数**。机制：`the edit model matches the MAJORITY aspect of its inputs` | 预裁全部参考图至 clay AR；提交前统计各输入 AR 并确认 clay AR 为多数 | 未裁则输出可能被重组为参考图比例（官方原话：`16:9 references quietly overrode the 2.39:1 clay frame`），须重裁 + 重生成 | fal 官方博客《From clay 3d render to a real action short》 | 一手 | **硬门**（条件生效） |
| B-03 | ⚠️**参考图数量存在隐藏上限**：多加参考图可能**反噬比例**——为"风格更准"多加若干 16:9 参考，会把 2.39:1 的 clay 投成 16:9 | 统计输入 AR 分布；对"再加一张参考"做收益/风险判断 | 削减参考图数量，或改走 B-01 基线（不传参考图） | 本团队自订（据官方"多数投票"机制的推论） | 自定 | 警告 |
| B-04 | 白模视频与输出 **fps 一致（默认 24）**；fps **只能作为受控变量单独实验**，**禁止在联调阶段与其他变量混用** | 调用参数留档并逐次核对 fps | 混用将导致**无法归因**（分不清是 fps 还是其他参数造成差异），该轮结果作废 | fal API schema（`frames_per_second` 默认 24；时长 = `num_frames / frames_per_second`）+ 本团队自订（联调禁止混用变量、fps 须与白模一致） | 一手 + 自定 | **硬门** |
| B-05 | **不得把 fps 当作"延长时长"手段**：成本与 cap 均基于**帧数**（`$ ∝ 宽×高×帧`；cap = `resolution × frames`），fps 只改回放速率。它是**回放速率杠杆（可做慢动作）**，**不是时长杠杆**；延长叙事必须增加帧数、因而增加成本 | 成本核算表按帧数计算，不按秒计算 | 若按"降 fps 省成本/延时长"做排期，会得到错误计划，须重做预算 | fal API schema：`时长 = num_frames / frames_per_second`；计费式与 cap 均为帧数基准 | 一手 | 警告 |
| B-06 | `intensity` **分阶段**：联调 `light`（keep more of the source render's look and **motion**，最保结构）→ 结构验收通过 → 终稿 `strong-v2`（fal 终稿设定即 strong-v2） | 分两轮调用并留档对比 | 联调直接用 strong-v2 会引入结构漂移，无法判断是"结构问题"还是"写实化副作用" | fal API schema（`intensity` 默认 light）+ fal 官方博客（终稿用 strong-v2） | 一手 | **硬门** |
| B-07 | prompt 模板**不要自己写 `3DREAL`**：该触发器由端点保证，`always kept, even if you clear it` | 模板只描述写实化后的结果 | 自己写会造成前缀重复，属无意义风险 | fal API schema，`prompt` 字段 | 一手 | 警告 |
| B-08 | **必须复核 output 回传的最终 prompt**，作为**免费的正确性自检**（可发现参数被平台静默改写） | 读取返回体中的最终 prompt 并断言包含 `3DREAL`、且与提交语义一致 | 断言失败即该次调用结果不采信、按缺陷记录 | fal API schema（最终 prompt 会回传在 output） | 一手 | **硬门** |
| B-09 | `enable_prompt_expansion` 保持默认 **false** | 调用参数留档 | 开启会引入不可控文本改写，破坏可复现性 | fal API schema | 一手 | **硬门** |
| B-10 | ⚠️**合规实测项**：`enable_safety_checker` 默认 **true**，我们的动作/冲突类题材**可能被默认拦截，必须实测确认** | 用真实题材样片实测；记录拦截情况 | **若受限，处置 = 走平台正规途径咨询条款与可用范围**。**不做任何规避** | fal API schema（`enable_safety_checker` 默认 true） | 一手 | 警告 |
| B-11 | ⚠️`video_quality` 默认 **high**（low/medium/high/maximum）：**是否影响计价或可用时长 ❓待核实** | 对比不同档位的返回体与计费明细 | **核实前不得假设它免费**；成本模型须为其预留不确定性 | fal API schema（未说明计价影响） | 未验证 | 警告 |
| B-12 | `detail_refine` 默认**关**；**仅终稿、且已通过结构验收的镜头**才开。原因：开启 = 像素 4.0×（成本 ×4）+ 额外一个处理阶段（更慢）+ **会把已验收的结构再交给模型改一次**（官方警告 `can drift further from the base`） | 分阶段调用；开关状态留档 | 联调期开启会污染"结构是否锁住"的判断，并使预算 ×4 | fal API schema（含 `detail_refine_strength` 默认 0.75，官方漂移警告） | 一手 | **硬门** |
| B-13 | 请求的 `resolution × num_frames` 必须落在 IC-LoRA cap 内（720p ~6s / 480p ~15s，超限返回 **422**） | 提交前用 D 段白名单校验；捕获 422 并记录 | 收到 422 即降档（720p→480p）或减帧；**不得重试同参数** | fal API schema，`resolution` 与 `num_frames` 两个字段（同一 cap 各述一次） | 一手 | **硬门** |
| B-14 | 每次调用**留档全部参数**：最终 prompt、resolution、intensity、fps、num_frames、detail_refine 及其 strength、seed、返回 requestId | 落盘 JSON（每镜一份） | 无留档则失败无法归因、成片无法复现 | 本团队自订（工程惯例） | 自定 | 警告 |

## C. 生成后验收

| 编号 | 判据 | 工具/命令 | 不过怎么办 | 出处 | 证据等级 | 硬度 |
|---|---|---|---|---|---|---|
| C-01 | 每次合成后做 **50% overlay 自检**：与白模帧 50% 混合，若边缘出现**重影（edges double）**即判定透视漂移 | ffmpeg `blend=all_mode=average` 生成对比图；逐镜抽帧目视/差分 | 判定漂移的镜头**不得进入下一阶段**；回溯 A/B 段参数并重生成 | fal 官方博客：`Verify with overlays, not vibes. If edges double in the 50% blend, the perspective drifted` | 一手 | **硬门** |
| C-02 | **ffmpeg 调用一律加 `-nostdin`** | `ffmpeg -nostdin -i ...` | 缺此参数会**静默破坏**输出（官方记录：整轮 3 个镜头首帧被毁），须重合成并复查首帧 | fal 官方博客（ffmpeg-in-a-loop bug 复盘） | 一手 | **硬门** |
| C-03 | 检查输出**宽高比 == clay AR**（防被多数投票改写） | `ffprobe` 读取输出宽高；与 A-01 记录比对 | 不一致即触发 B-02 复查；必要时回落 B-01 基线（不传参考图）重生成 | fal API schema + 官方博客 | 一手 | **硬门** |
| C-04 | **按实际文件解析** fps / 分辨率 / 时长，**不采信任务摘要** | `ffprobe -show_entries stream=width,height,avg_frame_rate -show_entries format=duration` | 摘要与实际不符时**以文件为准**；差异记入缺陷台账（生态中已见摘要 24fps 而文件为可变帧率 ~24.12fps） | 第三方实测（即梦 CLI 侧同类现象） | 二手 | **硬门** |
| C-05 | 结构项验收顺序：**镜头 → 构图 → 空间/相对位置 → 结构轮廓 → 视觉**。视觉**最后**看 | 对照白模逐项打勾（五项全过才算通过） | 前面任一项不过即退回，**不得**被"画面质感好"说服而放行 | 即梦官方白模案例流程 | 二手 | 警告 |
| C-06 | 记录每镜**重抽次数**，并按倍数计入成本核算 | 台账字段：镜号 / 尝试次数 / 采用 seed / 累计成本 | 未计重抽会低估总成本；报价须按含重抽的有效成本 | 第三方横评（成片普遍经 2–3 次抽卡选取） | 二手 | 警告 |
| C-07 | 输出与白模**逐帧比对并量化残余漂移**，重点盯官方已知漂移区：小尺度建筑细节、远景、轨道/构件数量、标牌、局部遮挡关系 | 逐帧差分或叠加图；对关键区域做人工抽检 | 漂移超可接受范围时：简化白模（减少自由解释空间）或加参考图（触发 B-02）后重生成 | 本团队自订（漂移区清单引自即梦白模实测的二手记录） | 自定 | **硬门** |

## D. 锚点与帧数白名单（参考表）

| 编号 | 判据 | 工具/命令 | 不过怎么办 | 出处 | 证据等级 | 硬度 |
|---|---|---|---|---|---|---|

## 二、三个待老板拍板的分叉（影响范围大，先定再动）

### 分叉 A：用哪个 Wan？（决定能否真验证"白模锁结构"）

| 选项 | 说明 | 是否验证白模锁结构 | 成本 |
|---|---|---|---|
| **A1（推荐）Wan2.1-VACE-1.3B 下全量** | 视频→视频条件化，吃白模视频+提示词，输出写实且**保留相机运动/人姿** | ✅ 正是我们的管线 | 下 ~4.31GB F16（¥0） |
| A2 用盘上 Wan2.2 TI2V 5B | 图→视频，只吃首帧+提示词，**自己生成运动** | ❌ 不锁结构（运动由模型抽卡，违背核心 thesis） | 0（已在盘） |

> **强烈建议 A1**：老板核心 thesis = "白模把抽卡不确定性消掉、结构定死"。TI2V 是图生视频、运动由模型编，**无法证明结构被锁定**；只有 VACE（视频条件化）能验证。A2 只能证明"本机能出写实视频"，证明不了我们的方法。

### 分叉 B：运行时怎么搭（严守铁律 #4 新根外只读）

| 选项 | 做法 | 合规 | 工作量 |
|---|---|---|---|
| **B1（推荐）归档 python 只读 + 新根脚本** | 克隆 Wan 官方推理代码进新根 `wan_runtime/`；用归档 `python_embeded`（torch cu130，只读执行）跑新根脚本；VACE 权重落新根 `models/`，VAE/文本编码器读归档（只读） | ✅ 新根外零写 | 中（克隆+写 loader） |
| B2 新根装独立 ComfyUI | 新根内装 ComfyUI + VACE 适配器 + 新 torch 环境 | ✅ 全在新根 | 大（重下 torch+cuda ~数 GB） |
| B3 改归档 ComfyUI | 往归档 `custom_nodes`/`models` 塞 VACE 适配器+权重 | ❌ **违反铁律 #4**（写新根外） | 小 |

> **建议 B1**：复用已验证的 cu130 torch，不重复下 CUDA 栈；新根只增代码+权重+产物，归档零改。

### 分叉 C：最小 L1 技术验证镜内容（请你定或认我的提案）

**我提案（最小、且直接测"结构锁定"）**：

| 要素 | 设定 | 为什么 |
|---|---|---|
| 场景 | 空房间（纯色地+墙，无杂光、无道具） | 排除干扰，只看"主体+相机"是否被保真 |
| 主体 | 1 个 MPFB2 低模人（站姿，保留头颈量感） | 最简单的"人"，验证人脸/身形不被抽卡漂移 |
| 动作 | 原地缓慢转体 90°（LINEAR 插值） | 简单可复核的姿势变化 |
| 相机 | 固定机位 + 慢 dolly-in（约 5s） | **关键**：相机运动必须由白模定死、写实后必须一致 |
| 时长/帧数 | **121 帧 @24fps = 5.042s**（fal 默认锚点，VACE 友好） | 对齐 R3 帧数枚举 |
| 产出 | 白模 RGB(PNG 序列) + EXR(Z/Normal) → VACE 写实化 → 对比"白模 vs 写实"验证结构一致 | 直接对应校验清单 A/B/C 段 |

> 评判标准：写实成片里**相机 dolly 轨迹 + 人转体 90° 必须与白模逐帧一致**（用光流中位速≥2px/帧 + 帧对齐差分核验），才算"白模锁结构"成立。

## 三、执行步骤（拍板后）

1. **下权重**：Wan2.1-VACE-1.3B F16 → 新根 `models/wan_vace_1.3b/`（HF，Apache-2.0，¥0）
2. **克隆 Wan 官方推理代码** → 新根 `wan_runtime/`（B1 方案）
3. **写 loader**：新根 `tools/r4_vace_runner.py`，调归档 python_embeded（torch cu130）加载新根 VACE 权重 + 归档 VAE/文本编码器
4. **建白模**：bpy 脚本直调（`-b` 后台）生成上述最小 L1 白模（RGB PNG 序列 + EXR Z/Normal），落 `blender/shots/r4_l1/`
5. **跑写实化**：VACE 吃白模视频 → 写实成片，落 `projects/r4_l1/03_render/`
6. **质检**：对齐 `qc_rubric` + 校验清单 A/B/C 段（光流/结构一致/无漂移）；音频本轮不做
7. **出 R4 报告**：白模 vs 写实对比 + 探针回显 + 是否"结构锁定"成立 → 交老板验收（一板块一验收）

## 2. ⭐ 五个会改变现有计划的发现（请重点看）

### ① 我们自己的三个阈值，**都没有行业出处**

| 阈值（已由老板 A3 拍板通过） | 检索结论 | 业界近邻 |
|---|---|---|
| **背景光流中位速 ≥ 2 px/帧** | **查不到任何出处**（已搜 Google/arXiv/CSDN/知乎） | GMFlow 的 `S_Move`(>0.5 保留)、EPE 指标；且"像素/帧"**非尺度不变**，业界建议**按帧对角线归一化** |
| **人脸 ArcFace 余弦 ≥ 0.75** | **无行业基准**；InsightFace 在 LFW 的**官方推荐阈值是 0.363** | NIST FRVT：固定阈值不通用，**假拒率跨人群差 10–100 倍** |
| **口型 Sync-C ≥ 5** | **无官方定义**；它落在"随机 ≈2 / 真人 ≈6.7–8.8"之间 | SyncNet 公开权重**仅英语训练** → 中文必须自建基线 |

**意味着什么**：这三个数是**我们自己定的严阈值**，不是抄来的标准。**作为"内部质量门"完全可以用**（严格些没坏处），但——
- **不能对外宣称是行业标准**（会被打脸）；
- **必须自建 golden 基线**：同一批镜头上先跑一遍，看我们自己的分布落在哪，再决定阈值。这一步是 **R3 的活**。
- **ArcFace 另有一条硬要求**：单帧完全不可信（seed 方差 σ≈0.09，相邻 seed 跨 0.18–0.42）→ **必须多帧投票 + 只取 |yaw| < 45° 的检出帧**。

### ② R4 技术验证镜**可以零成本先跑通**

**Wan2.1-VACE-1.3B**：Apache-2.0，**≈8.19GB 显存可跑**，权重 F16 = 4.31GB（或 GGUF Q8 = 2.32GB）。
本机那份残片只有 196MB，**缺口已精确定位**。补齐后**不用花一分钱**就能验证"白模 → 写实化"链路跑得通——再决定要不要上云引擎。
（另外 Wan2.2-Fun-Control / VACE-Fun 量化后 6–12GB 可跑但极慢，列为 480p 短片段备选。）

### ③ 旧项目的音频欠账，根因找到了

旧项目 8 条对白混响欠账（"缺 IR，用 `aecho` 近似"）——**根因是 `aecho` 本身就是固定延迟回声，不是空间混响**。
**正解：ffmpeg `afir`（`af_afir.c`，LGPL）卷积真 IR。** 这一条直接解决旧项目 10 项 blocked + 8 项 approx 的一半。

### ④ edge-tts 从"黄灯"升级为"必须换"，现在有条款原文了

微软《可接受的使用政策》禁止「使用任何**自动化过程或服务**来访问或使用本服务，例如 BOT、蜘蛛程序或定期缓存 Microsoft 存储的信息」；《Services Agreement》禁止「**web scraping, web harvesting, or web data extraction**」。
实测同 IP 高频请求直接 **403**；微软官方贡献者称**无公开商用文档**。
→ **替代已定：CosyVoice 3（代码+权重双 Apache-2.0，18 方言，指令控情绪，0.5B 需 6–8GB）为首选；GPT-SoVITS（双 MIT）为备用。**

### ⑤ 一个"检测项比正片还慢"的坑（会拖垮流水线）

`signalstats` 实测 **1080p30/120s 耗时 29.56 秒——比一次完整编码还慢**。**必须抽样中心区**，不能全片跑。
另两条也是静默陷阱：`loudnorm` 的 `linear=true` 会因缺 measured / 超 TP / LRA 超限而**静默回退 dynamic**（不报警）→ 第二遍必须加 `print_format=summary` 复核实际模式；`alimiter` 默认 `level` 会**二次抬回 0dB** → 必须 `level=disabled`。

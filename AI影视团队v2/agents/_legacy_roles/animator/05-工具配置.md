## 二、技术选型（已实测修正 v1.1）

**方案：AnimateDiff-Lightning（字节开源）+ DreamShaper_8（SD1.5底模）**

> ⚠️ **2026-09-25实测修正**：AnimateDiff-Lightning的motion module是 **SD1.5系**（官方示例底模toonyou_beta6即SD1.5），
> 与sd_xl_base_1.0（SDXL）**不兼容**（提交即报MotionCompatibilityError）。
> 已补下载SD1.5底模 `DreamShaper_8_pruned.safetensors`（约2.1GB，写实/风格通吃）专门用于视频生成。

| 维度 | 结论 |
|------|------|
| 生态 | **SD1.5生态**（视频专用底模，与出图的SDXL管线并行，互不影响） |
| 速度 | 相比原版AnimateDiff提速10倍以上，前后一致性表现好 |
| 能力 | t2v（文生视频）/ v2v（ControlNet姿态控制）/ i2v（首帧锚定，denoise控制动效强度） |
| 输出 | Video Helper Suite的VHS_VideoCombine节点直接出MP4 |

**生成参数基准（AnimateDiff官方指引）：**
- 分辨率：512x512（t2v）或704x384（i2v 16:9）起步——**SD1.5上限，禁1024**
- 帧数：16帧基本动画（2s @8fps）
- 采样：steps=4 / cfg=1.0 / euler / sgm_uniform（cfg=1时负面词无效）
- i2v denoise基准：0.65（低=贴近首帧，高=动态大但易崩）
- 关键限制：**单次生成时长短**，80s全片不能整片直出

## 四、MVP策略（预算与时长的务实平衡）

80s全片×30fps=2400帧，单卡全动态不现实。采用**分层动效**：

| 层 | 镜 | 动效 | 成本 |
|----|----|------|------|
| 关键镜 | 3-3绿眼亮起、4-1归途 | AnimateDiff动态片段 | 高 |
| 次关键 | 1-2空猫窝、3-4伸手、4-3影子 | 动态或Ken Burns | 中 |
| 普通镜 | 其余 | 静帧+Ken Burns（剪辑层推拉/平移） | 低 |

**降级不阻塞**：视频模型未部署时，全片走静帧+Ken Burns，镜头清单标注"动效待部署"，剪辑师先剪节奏。

## 五、工作流JSON模板（已部署 ✅）

CLI调用（tools/comfyui_client.py，视频输出到项目 `shots/` 目录）：

```
# i2v（首帧锚定，分镜图→动态mp4）
python tools/comfyui_client.py video <项目路径> <镜头名> --mode i2v \
  --anchor <分镜图路径> --prompt "<运镜+动作prompt>" \
  --width 704 --height 384 --frames 16 --fps 8 --denoise 0.65

# t2v（文生视频，无锚点）
python tools/comfyui_client.py video <项目路径> <镜头名> --mode t2v --prompt "..." --width 512 --height 512
```

实际模板结构（comfyui/animatediff_i2v.json，API格式）：
```
LoadImage(锚点) → ImageScale(704x384 center-crop) → VAEEncode
  → RepeatLatentBatch(16帧) → KSampler(steps4/cfg1/euler/sgm_uniform/denoise0.65)
  → VAEDecode → VHS_VideoCombine(h264-mp4/crf19)
其中 model 流：CheckpointLoader(DreamShaper_8) → ADE_AnimateDiffLoaderGen1(4step Lightning)
```

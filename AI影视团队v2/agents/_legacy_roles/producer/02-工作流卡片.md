# Agent 工作流卡片：制片人

## 人工原流程

| 步骤 | 动作 | 耗时 | 判断点 |
|------|------|------|--------|
| 1 | 收到老板在对话界面发来的创作指令 | 即时 | 指令是否明确？太模糊就追问 |
| 2 | 复述指令，等老板确认理解一致 | 即时 | 老板说"对"才继续；纠正了就重新理解 |
| 3 | 读取/创建导演意图文档，对齐方向 | 即时 | 新指令与已有文档冲突？冲突→问老板以谁为准 |
| 4 | 确定这1个镜头要生成哪些资产，排依赖顺序 | 1分钟 | 哪些步骤必须？顺序对不对？有没有可跳过的？ |
| 5 | 按依赖顺序调ComfyUI生成第一个资产 | 30秒-2分钟 | 生成成功？预算是否接近上限？失败→重试1次 |
| 6 | 展示生成结果给老板预览 | 即时 | （老板判断）满意→锁定；不满意→调参 |
| 7 | 不满意→调参重新生成；满意→锁定到K13 | 30秒-2分钟/次 | 重试2-3次仍不对→停下让老板介入 |
| 8 | 所有资产锁定后，汇总成果向老板汇报 | 即时 | 全部完成？有遗漏？汇报简短文本 |

## 关键判断点和判断依据

1. **指令是否明确** → 依据：是否包含具体内容方向（如"30秒雨夜短片"vs"做个好看的"）
2. **理解是否一致** → 依据：老板复述确认后说"对"才继续
3. **意图文档冲突** → 依据：新指令与已有文档的方向/风格矛盾
4. **依赖顺序** → 依据：角色图→场景图→分镜→动画，上游是下游的输入
5. **生成是否成功** → 依据：ComfyUI正常返回结果，无报错
6. **预算是否充足** → 依据：剩余预算是否>0，低于20%提醒，耗尽熔断
7. **老板是否满意** → 依据：老板预览后确认或要求修改
8. **重试上限** → 依据：同一资产重试2-3次仍不满意，停下让老板介入
9. **是否全部完成** → 依据：资产清单中每项都已锁定

## 最终确认版 Agent 工作流

### 触发条件
收到老板在对话界面发送的创作指令。

### 步骤

1. MUST 确认收到指令。如果指令模糊（缺少具体内容或方向），MUST 追问"请补充具体方向"。
2. MUST 复述指令内容，等待老板确认。老板纠正后 MUST 重新理解并再次复述。
3. MUST 读取导演意图文档。文档不存在时 MUST 创建新文档。新指令与已有文档冲突时 MUST 停下问老板"以新指令为准还是保留原文档"。
4. MUST 根据指令+意图文档，确定本镜头资产清单和依赖顺序。SHOULD 跳过不必要的生成步骤。
5. MUST 按依赖顺序调用ComfyUI逐个生成。每次生成前 MUST 检查预算余额。余额低于20%时 SHOULD 提醒老板。余额耗尽时 MUST 停止。
6. MUST 把每次生成结果展示给老板预览。
7. 老板不满意时 MUST 调整参数重新生成。重试超过2次仍不满意时 MUST 停下请老板介入。老板满意时 MUST 锁定该版本到K13版本树。
8. 所有资产锁定后 MUST 汇总成果向老板汇报，MUST 使用简短文本格式。

## 成功标准
- 所有资产按依赖顺序生成完成
- 每个资产经老板预览确认并锁定到K13
- 无遗漏资产
- 未超出预算

## 失败处理

| 失败情况 | 处理方案 |
|---------|---------|
| 指令模糊 | 追问直到明确 |
| 意图文档冲突 | 停下问老板 |
| ComfyUI生成失败 | 重试1次；再失败报告老板 |
| 预算耗尽 | 自动停止，通知老板 |
| 重试2-3次老板仍不满意 | 停下，请老板介入调参或改需求 |

## 人工兜底
- 指令与意图文档冲突 → 老板决定方向
- 生成结果反复偏离意图 → 老板介入调参
- 预算熔断 → 老板决定是否追加预算
- 敏感/不可实现内容 → 老板确认替代方案
- 主要检查环节：**预览环节**

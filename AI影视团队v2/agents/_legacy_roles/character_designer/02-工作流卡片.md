# Agent 工作流卡片：角色设计师

## 人工原流程

| 步骤 | 动作 | 耗时 | 判断点 |
|------|------|------|--------|
| 1 | 收到编剧发来的角色描述（姓名、年龄、性格、着装） | 即时 | 描述是否够具体？只有"好看的女孩"就追问 |
| 2 | 复述理解：性格如何翻译成长相特征 | 即时 | 编剧说"对"才继续；纠正了就重新翻译 |
| 3 | 用浏览器搜索参考图（ArtStation/Pinterest、类似气质角色） | 1-2分钟 | 参考图气质是否匹配角色性格？搜不到就换关键词 |
| 4 | 确定特征关键词清单+角色色板 | 1分钟 | 和场景色板冲突？冲突→调整角色配色 |
| 5 | 调ComfyUI生成第一张正面定调图 | 30秒-2分钟 | 生成成功？失败→重试1次 |
| 6 | 自检：辨识度够？特征全体现？色板不冲突？ | 即时 | 不达标→调参；达标→进审核 |
| 7 | 提交艺术总监定调审核，附参考图+特征关键词 | 即时 | （艺术总监判断）通过→出三视图；退回→改 |
| 8 | 定调通过→生成三视图（正/侧/背）+基础表情集 | 1-3分钟 | 三视图是否像同一个人？跑形→重生成 |
| 9 | 退回→按修改方向调参重生成；通过→锁定K13+写character_lock | 30秒-2分钟/次 | 退回2-3次→停下让艺术总监或老板介入 |
| 10 | 所有角色锁定后，汇总成果向艺术总监汇报 | 即时 | 全部完成？有遗漏？汇报简短文本 |

## 关键判断点和判断依据

1. **角色描述是否明确** → 依据：是否包含具体性格+身份+着装（如"18岁安静女大学生，米色风衣"vs"好看的女孩"）
2. **性格翻译是否一致** → 依据：编剧复述确认后说"对"才继续
3. **参考图是否匹配** → 依据：参考图气质与角色性格描述是否传达同一种人
4. **色板是否冲突** → 依据：角色主色与场景主色是否在色环上过于接近（<30度色相差）
5. **定调图是否达标** → 依据：特征关键词≥3个且画面全部体现，第一眼有辨识度
6. **三视图是否一致** → 依据：正/侧/背是同一个人（发型、五官、体型、服装一致）
7. **艺术总监是否通过** → 依据：艺术总监说"通过"或"锁定"；退回必须带"哪张图+哪个特征跑偏+修改方向"
8. **退回上限** → 依据：同一角色退回2-3次仍不通过，停下请艺术总监给明确方向或老板介入
9. **是否全部完成** → 依据：角色清单中每个角色都已锁定（含三视图）

## 最终确认版 Agent 工作流

### 触发条件
收到编剧通过对话界面或任务系统发来的角色描述。

### 步骤

1. MUST 确认收到角色描述。如果描述模糊（缺少性格或身份），MUST 追问编剧"请补充角色性格和身份背景"。
2. MUST 复述理解——把性格翻译成外貌特征（如"安静内向"→"内敛眼神、简单发型、素色着装"），等待编剧确认。编剧纠正后 MUST 重新翻译并再次复述。
3. SHOULD 用浏览器搜索参考图（ArtStation/Pinterest角色设定、类似气质角色）。SHOULD 搜2-3组不同关键词拓宽方向。
4. MUST 确定特征关键词清单（发型/发色/服装/标志性配饰，≥3个）和角色色板。MUST 检查与场景色板是否冲突，冲突时 MUST 调整角色配色。
5. MUST 调用ComfyUI生成第一张正面定调图。生成前 MUST 检查预算余额。
6. MUST 自检：特征关键词是否全部体现在画面里？第一眼是否有辨识度？色板是否与场景冲突？
7. MUST 提交艺术总监定调审核，附参考图和特征关键词列表。MUST 使用简短文本（不超过100字）。
8. 艺术总监退回时 MUST 按修改方向调参重新生成。退回超过2次仍不通过时 MUST 停下请艺术总监给明确方向。
9. 定调通过时 MUST 用 `tools/three_view_client.py` 生成侧面/背面视图（正面即定调锚点图），和基础表情集（3-5个表情）。三视图生成策略（2026-09-26实测）：纯文生图 + 视图短语前置 + `--strip` 剥离姿势/构图锚词（portrait/sitting等）+ 新seed，身份由prompt_injection承载；img2img勿用（denoise 0.6下锚点构图主导，输出仍是正面）。MUST 自检三视图人物一致性（发型/体型/服装）。
10. 特征漂移（如发型跑形）时 MUST 用 `--reinforce`（特征强化短语）+ `--negative-extra`（负面词压制）重生成该视图。三视图齐全且一致时 MUST 锁定版本到K13版本树（每视图单独lock），MUST 写入 `character_lock/{角色名}.json`（含prompt_injection字段和三视图路径）。
11. 所有角色锁定后 MUST 汇总成果向艺术总监汇报，MUST 使用简短文本格式。

## 成功标准
- 所有角色按编剧描述生成完成（定调图+三视图+表情集）
- 每个角色特征关键词≥3个且画面全体现
- 三视图人物一致性过关（正/侧/背是同一个人）
- 每个角色经艺术总监审核通过并锁定到K13
- character_lock JSON 已写入，下游可自动获取特征注入
- 色板与场景不冲突
- 未超出预算

## 失败处理

| 失败情况 | 处理方案 |
|---------|---------|
| 角色描述模糊 | 追问编剧直到明确 |
| 参考图搜不到 | 换关键词重搜；再搜不到用文字描述直接生成 |
| ComfyUI生成失败 | 重试1次；再失败报告艺术总监 |
| 色板冲突 | 调整角色配色避开场景主色 |
| 三视图跑形 | 勿用img2img（转体失败）；用three_view_client纯txt2img+剥锚词重生成该视图；发型等特征漂移→`--reinforce`+`--negative-extra`（雨夜寻猫实测：林小雨back需3次尝试）；多次跑形请艺术总监判断是否降级单视图 |
| 艺术总监退回2-3次 | 停下，请艺术总监给明确修改方向或请老板介入 |
| 预算耗尽 | 自动停止，通知制片人和艺术总监 |

## 人工兜底
- 角色描述模糊 → 编剧补充明确
- 退回2-3次仍不通过 → 艺术总监给明确方向或老板介入
- 色板冲突无法自动解决 → 场景设计师和艺术总监协调
- 三视图跑形严重 → 艺术总监判断是否降级单视图交付
- 预算熔断 → 老板决定是否追加预算
- 敏感/不可实现角色形象 → 艺术总监确认替代方案
- 主要检查环节：**艺术总监定调审核环节**

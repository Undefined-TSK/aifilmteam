# 维度 19 · 硬件资源调度与散热瓶颈

## 0. 结论先行

1. **12GB 单卡是本项目唯一共享 GPU**，Wan2.2 5B 实测峰值 10596 MiB，距 12GB 红线（名义 12288 MiB / 实测总容量 12231 MiB）仅余约 1.4 GiB —— 单引擎已到「一碰就 OOM」边缘。
2. **散热降频数据缺失**：本机无持续负载温度采样记录，温度曲线一律标 `待实测`，本维度只给实测方案，不编造温度。
3. **RAM 比 VRAM 更紧**：实测物理内存 15.5 GiB、当前空闲仅 2.3 GiB；Blender + Ollama + ffmpeg 同时运行即触顶，是比显存更早爆的一环。
4. **vram_lock 的 TTL 语义有真实隐患**：TTL=1800s 恰等于 Wan2.2 单任务轮询上限，长任务超时会被判「过期锁」而被后到者接管（`took_over_from` 语义），并非自动保护。
5. **调度结论**：GPU 重任务必须串行（已有纪律，R0-T6 已实测证明），云端引擎（fal / 即梦 / 百炼）不占本地 VRAM、豁免接锁，是 R5 唯一可并行扩张的算力。

## 3. vram_lock 极端场景评估（TTL 过期）

代码事实（`AI影视团队v2/tools/vram_lock.py`）：

| 参数 | 值 | 语义 |
|---|---|---|
| DEFAULT_TTL | 1800 s | 心跳超过 TTL 未续租 → 锁被判「过期」可被抢占 |
| HEARTBEAT_SEC | 60 s | 后台守护线程续租间隔 |
| POLL_SEC | 5 s | 抢锁轮询间隔 |
| 释放方式 | `os.replace` 写 `released` 标记 | 沙箱禁删，锁文件长期存在属正常 |
| 抢占语义 | 过期强抢记 `took_over_from` | 正常释放后重获记 `acquired_normally` |

**极端场景推演**：

1. **心跳线程未死但主任务卡死**：心跳线程独立于主任务，只要进程活着就每 60s 续租 → 锁不会过期，但 GPU 被僵尸任务占住，直到进程被杀。**风险：锁活着 ≠ 任务健康**。
2. **进程被强杀（OOM / 任务管理器结束）**：心跳线程随之消失，锁进入「心跳静默」，1800s 后自动可被接管。**代价：最长 30 分钟空窗**，期间后到者要么等（wait_sec 上限 1800）要么报错退出。
3. **TTL=1800s 恰等于 Wan2.2 单任务轮询上限**（审计件 E9/D4 已点明）：一个接近上限的长任务，其心跳若因 GC/系统挂起短暂停顿，可能被误判过期而被接管 → **两进程同抢 12GB 显存 → 直接 OOM**。这是当前实现的真实隐患，非理论风险。
4. **正确姿势**：长任务应显式传入更大的 `ttl`（如 3600），或把「进程存活检测」与「心跳」解耦；仅靠 1800s 默认值不足以保护 Wan2.2 这类长任务。

## 4. 硬件资源调度策略（R5 落地）

1. **串行纪律（已生效）**：任何本地 GPU 引擎 submit 前必须 `vram_lock` 独占；R0-T6 已实测两任务时间窗交集 0.0s，串行化成立。
2. **重任务分时段**：Wan2.2 5B（≥8GB）与 Blender/质检类任务错峰；轻任务（EEVEE 白模、图生图）在等待窗口排队。
3. **温度熔断（待实测落地）**：以 `nvidia-smi --query-gpu=temperature.gpu` 每 2s 采样，设定「温度 > 85 C 或 SM 频率跌至上限 60% 以下且持续 > 30s」→ 暂停新任务提交、等冷却；阈值须用本维度 §5 实测标定后再定。
4. **OOM 降级梯度**：Wan2.2 分辨率 896x512 → 832x480 → 帧数减半 → 切云端（百炼 wanx / fal）；ComfyUI 一律 `--lowvram` 启动。
5. **RAM 护栏**：禁止 Blender + Ollama + VLM 三开；VLM 质检（约 10GB 显存）必须单独时段，且质检前先释放 ComfyUI 常驻（约 8.7GB）。
6. **磁盘 I/O**：EXR 序列帧是 I/O 大户（outputs/ 实测 360 个 EXR 合计 96.9 MB，单镜多帧 PNG 合计 1254 张 / 123.5 MB）；R5 18 镜全量渲染前应先清理 `control_test/`、`_check_*` 等探针残留，避免读写放大。

## 5. 散热实测方案（本维度无数据，给出可执行方案）

| 步骤 | 命令 / 操作 | 采集项 | 目标 |
|---|---|---|---|
| 1 | 空载基线 60s 采样 | 温度 / 频率 / 功耗 / 利用率 | 已得：43 C / 330 MHz / 6.23 W / 0% |
| 2 | 起 Wan2.2 5B 生成，全程 2s 采样 | 同上 + `clocks_throttle_reasons` | 定位是否触发 thermal slowdown |
| 3 | 连续跑 3 个 127s 任务（模拟 R5 批量） | 温度爬升斜率 | 得出「第几镜开始降频」 |
| 4 | 记录降频点频率 / 温度 | `nvidia-smi -q -d PERFORMANCE` | 标定熔断阈值 |
| 5 | 冷却回落到空载温度的时间 | 采样 | 得出「冷却窗口」时长 |

采样命令（PowerShell）：

```powershell
nvidia-smi --query-gpu=timestamp,temperature.gpu,clocks.sm,clocks.max.sm,power.draw,utilization.gpu,clocks_throttle_reasons.active --format=csv -l 2
```

> 未跑第 2~5 步前，`散热降频温度曲线.html` 中的温度序列一律显示 `待实测`，只保留空载实测点。

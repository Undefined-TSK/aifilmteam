## 0. 命题：控制不是越紧越好，控制的位置决定创意流向

R17-8 的核心判断是：原 17 号草案把"灵活的文本意图"死板翻译成"固定 Blender 数值"，等于在管线最上游就把创意杀掉了——后面 S2-S5 四道门全部在验收"翻译是否精确"，没有任何一环在收割"生成是否惊喜"。已实证的 VACE 案例恰好说明这一点：深度条件保几何、prompt 驱动语义，台灯被重绘成"发光方块"不是失败，而是**接口设计决定了模型的自由度流向了哪里**——接口把自由度放错了地方，它就流向荒诞；放对了地方，它就流向创意。

**本设计的总纲：把"控制"从"逐数值对账"改写为"分层锚点"——白模只锚住叙事必须成立的东西（空间/轨迹/节拍/存在性），其余全部让给生成模型，并用抽卡机制把不确定性从"风险"变成"选题库"。**

## 1. 调研综合：主流解法怎么做"约束 × 创意"平衡

### 1.1 学术前沿：稀疏几何 blocking 正是"白模为骨"的形式化

| 工作 | 核心思路 | 对本项目的直接启示 |
|---|---|---|
| **LooseControlVideo**（Adobe Research，arXiv 2606.19495，2026-06） | 用**稀疏有向 3D 盒子**作为"blocking"代理（借自真人电影排戏的走位术语）：用户只编排高层布局+轨迹+时序，模型推断次级动态与形变。论文明确指出：深度条件混淆了两个控制轴——①布局/运动/遮挡（导演该管的）②细粒度姿态/形变（该放给模型的）。Trajectory Error 改善 1.2-3×、遮挡精度提升 1.5-2× | **白模=电影工业的 blocking 阶段，这个类比有了直接论文支撑**。原 17 号草案的 G3"机位 ±5% 数值门"就是在硬管②轴，属控制错位 |
| **CoaG: Cylinders on a Grid**（arXiv 2609.24208，2026-09） | 回答"最少要画多少几何才能同时控制人物站位和镜头运动"——答案是**地面网格+每人一个圆柱体**。外观全部来自 text prompt + 背景参考图；布局与运动全部来自几何。在 Wan2.2-Fun-Control 上训练 LoRA 实证：人物数量/顺序/位置/身高全跟随圆柱，dolly-in/orbit/pan/crane 路径全跟随，而"他们是谁、穿什么"由文本自由决定 | **直接验证了 R17-8 哲学的可行性**：基本体白模（我们正是 cube/cylinder 拼装，01-blender D4）+ prompt = 足够的控制信号。我们的五件套（深度/Normal/IndexOB）比它还富裕 |
| **VideoDirectorGPT**（openreview，LLM 视频规划+Layout2Vid） | LLM 先产出"video plan"（场景描述+实体清单+逐帧 bounding box 布局+一致性分组），下游模块消费 plan 生成；**支持动态调节 layout guidance 强度** | 与我们 intent_graph→scene_skeleton 双契约同构，佐证契约设计方向正确；"强度可调"启示见 §1.2 |
| DyST-XL（themoonlight.io 评述） | LLM 解析 prompt 为实体-属性图→物理感知关键帧布局→双 prompt 控制注意力（实体级局部对齐） | 实体级对齐思想可用于"逐几何体语义标注"（§4） |

### 1.2 工程实践：控制强度是"旋钮"不是"开关"

- **ControlNet 生态共识**（MindStudio 深度图教程 mindstudio.ai/blog/depth-maps-as-storyboards-ai-video-generation；apatero.com ControlNet 指南与视频堆叠指南 2025）：深度条件权重 0.3-0.5=轻引导（模型自由发挥、大致守结构，适合风格化）；0.6-0.8=强引导（空间精确优先）；0.9+=机械跟随、反而伤连贯性。多 ControlNet 叠加时总强度 >2.0 通常崩坏——**"把所有轴全部锁死"在工程上就是坏的**，这为"分层放开"提供了量化依据。
- **时间窗口控制**（CSDN 实践文 blog.csdn.net/leohou72073/article/details/160833194）：ControlNet 的 start_percent/end_percent 可实现"前 3 秒高控制、后 7 秒放开"的**由紧到松**——控制不必全程恒定。本地 LVACE（ComfyUI VACE-1.3B）可复用此思路做"锚住开头、放开中段"的变奏实验（未验证，试点项）。
- **VACE 官方能力面**（GitHub Wan2GP docs/VACE.md；comfy.icu/node/WanVACEVideoRepainting；DeepWiki kijai/ComfyUI-WanVideoWrapper §13.4）：①`control_condition` 可选 depth/pose/scribble；②`strength` 0-1.0 是官方明确的"保真度旋钮"；③`ref_images` 参考图位可注入人物/物体/场景，官方建议"prompt 中显式描述注入对象"；④视频蒙版可区域化控制。云端 vace-plus 的 repainting 接口原生带 ref_images_url 与 strength——**我们的"白模可读性"与"控制分层"两条设计在云端接口上都有现成挂点，零额外开发**。
- **CFG/去噪分层**（comfyui.org Wan2.1 VACE 教程）：KSampler denoise、FluxGuidance 值调节"细节与稳定性"平衡——本地管线里这些都是逐层可调旋钮。

### 1.3 专业管线怎么处理"导演意图 vs 模型自由发挥"

- **全 AI 剧场电影《GRANDMALEVIT》实做流程**（博报堂访谈 seikatsusha-ddm.com/article/16273，2025-10）：导演山口ヒロキ的工作流=逐 cut 先生成第 1 帧→**5 种视频生成工具分别生成同 cut→比较择优**（例：同一道具场景 Runway Gen-3 胜出、战斗转身镜头 Kling 1.6 胜出）；导演写演出/运镜指示、助理生成、导演验收。**没有一条"数值对账"环节，全部是"多候选+人审"**。
- **ReelMind Nolan"Agency vs Inspiration"框架**（reelmind.ai 两篇 2025 博文）：结构化规划（叙事弧/角色一致性/节拍）由 Agent 管，"happy accidents"靠 prompt 分层+多模型引入，人保留**否决权**而非参数填写义务。
- **3-pass 工作流**（moltbook.com 社区实践："generate many, select few, polish winners"）：Pass1 便宜快速产 6-12 个草稿候选（480-720p）→Pass2 零成本人工挑选可剪在一起的 2-4 个→Pass3 只对胜者投入贵引擎高清重生成。成本测算：比"一次求完美"省 ~50% 成本、~55% 时间。**瓶颈不在模型质量而在选择质量**。
- **Best-of-N 的学术工程化**（腾讯新闻对 FIRM-Video 论文的报道 news.qq.com/rain/a/20260904A0BW0E00；arXiv 2603.01509 "3R" 方法）：N=8 候选→VLM 评分器（FIRM-Video-8B / Qwen3-VL-8B / VideoScore2）择优，VBench 三维（质量/语义/一致性）全面优于随机采样；**评分权重应重语义正确性与物理合理性、轻主观美感**（VisionReward-Video 权重表：top 权重全在"是否满足文本要求/运动是否真实"，光照美感权重很小）——这直接指导我们 VL 评分维度设计（§3.3）。

### 1.4 调研结论（一句话）

主流解法殊途同归：**几何/布局/轨迹用稀疏信号锚（白模/盒子/圆柱），外观/语义/微动态全部让给 prompt，强度用旋钮分层，产出用 N 候选+VLM 初选+人审定案**。没有一家在逐帧对账相机数值。

## 2. 控制分层表：白模刚性锚点 vs AI 创造自由区

> 设计原则：锚点必须是"错了会毁叙事/毁剪辑/毁跨镜连贯"的东西；其余一切，锚而不锁（白模给倾向，模型做决定）。

### 2.1 刚性锚点（白模保留，验收硬门或软门）

| # | 锚点 | 白模承载方式 | 为什么必须锚 | 验收方式 |
|---|---|---|---|---|
| A1 | **空间布局与遮挡关系** | scene_skeleton 对象位置/粗尺寸 → 白模渲染 → 深度条件 | 跨镜空间连贯是观众空间感的底线；"猫窝在窗边"换镜后跑到门口=穿帮 | 深度序列比对 + VL 判读（软门） |
| A2 | **元素存在性**（必须有/不能有） | intent_graph 元素清单 → 白模对象树 + prompt 正/负例 | 剧情承诺（空猫窝、绿眼）缺位=叙事断裂；禁用项出现=导演红线 | **保留 G2 元素覆盖硬门** |
| A3 | **运动轨迹与运镜方向** | camera 轨 move_type（dolly/pan/truck/static）→ 白模相机关键帧 | "推向猫窝"与"从猫窝拉开"是相反的叙事；方向不能交给模型猜 | 白模深度序列自带轨迹 + VL 二值判读"是否推近/横移"（软门，**替代原 G3**） |
| A4 | **节拍时长** | edit 轨 in_f/out_f → 8k+1 帧数 | 成片剪辑与配乐的骨架，秒级都不能漂 | **保留 G3b 帧数零误差硬门** |
| A5 | **跨镜场景一致** | 同 SET 骨架复用（2-1/2-4 同街道） | 观众脑内地图靠重复建立 | scene_skeleton 复用校验（机器，轻量） |

### 2.2 创造自由区（放开给模型，白模最多给"倾向"）

| # | 自由区 | 原方案死板处 | 放开后创意流向哪里 | 白模剩余角色 |
|---|---|---|---|---|
| F1 | **材质语义/外观**（台灯长什么样、猫什么花色） | 无（本来靠 prompt） | VACE ref_images + prompt；"发光方块"式惊喜在此区是**资产**不是事故 | 白模基本体仅给形状/位置暗示 |
| F2 | **氛围光色**（2900K 数值→"暖黄孤灯"情绪词） | light 轨逐帧数值对账（G 系隐含） | prompt 情绪词；模型对"雨夜霓虹"的理解远超数值翻译 | light 轨数值降级为 prompt 生成参考（§5 改写项） |
| F3 | **微动态**（雨滴、窗帘飘动、猫尾、霓虹闪烁） | 白模走位/插值全契约化（17 号草案 S4） | 模型自由生成——这正是 t2v 最强项 | 不锚 |
| F4 | **构图变体**（三分法 vs 居中、留白多少） | 分镜参考图 VL 反推布局进 scene_skeleton（17 号草案 S2③） | 白模只锁"谁和谁的相对位置"，精确画面构图留给每镜抽卡 | 布局给相对关系，不锁画面坐标 |
| F5 | **镜头语言变奏**（focal 85mm 数值→"特写压迫感"） | camera 轨 focal_mm 精确相等硬门（G3） | prompt 镜头语言词 + 模型自选景别微调 | move_type 方向锚（A3），数值全放 |
| F6 | **角色表演细节**（走位节奏、肢体语言） | performance 轨空物体路径关键帧 | 锚起点/终点（A1 布局），中间过程模型自由 | 首尾位置锚点 |

## 3. 三个机制设计

### 3.1 意图档位机制：intent_graph 契约字段修改建议

原 intent_graph 是单一"结构化事实源"，所有下游一律对账。改为**三档位标注**，每个约束项挂 tier 字段：

```jsonc
// intent_graph.json 约束项示例（新增 tier 字段）
{
  "element_id": "E-003",
  "name": "空猫窝",
  "tier": "locked",            // locked | proposed | free
  "anchor": "existence",        // 该项锚的是哪个轴: existence/layout/trajectory/duration/none
  "source_span": "分镜表 1-2 description",   // 溯源不变
  "prompt_hint": "窗边一个空的藤编猫窝，垫布翻起",  // 自由区→prompt 语义而非数值
  "acceptance": "hard"          // locked→hard 门; proposed→soft 门(VL 参考分); free→不验收
}
```

| 档位 | 定义 | 典型内容 | 验收 | 谁定 |
|---|---|---|---|---|
| **locked（导演钦定）** | 改了就不是这部片 | 元素存在性/禁用项（A2）、镜时长（A4）、剧情节拍、场切换顺序 | 硬门（G2/G3b 保留） | 导演签收，不可自动变更 |
| **proposed（LLM 提案区）** | 系统给默认值，导演可改可放 | move_type 方向（A3）、光源方向语义、场景切换点 | 软门（VL 语义判读，FAIL 转人审不自动打回） | P1/P2 提案 → 导演确认或改写 |
| **free（完全自由区）** | 白模只给倾向，模型做主 | 材质/光色/微动态/构图/景别/表演细节 | 不验收；VL 评分只进抽卡选择器不进门 | 模型，导演事后挑选 |

- **契约修改最小化**：intent_graph/scene_skeleton 双契约结构保留，新增 `tier`/`anchor`/`prompt_hint` 三字段（Pydantic 加可选字段，向后兼容）；scene_skeleton 的 pos_m/size_m 语义从"精确米制"放宽为"相对关系正确即可"（G1 空间自洽门保留但判据从数值改为拓扑关系：谁在谁旁边/前面）。
- **档位流转**：任何 proposed 项导演可一键升 locked 或降 free；抽卡若在 free 区产出了导演喜欢的变体，可"收割"——把该变体描述写回 prompt_hint 并升 proposed（**这是"收割不确定性"的制度化**）。

### 3.2 四门验收按新哲学修正（对应任务书"修正原 1:1 四门"）

| 原门 | 处置 | 新形态 |
|---|---|---|
| G2 元素覆盖（硬） | **保留** | 不变：元素 100% 存在、禁用 0 出现——这是 A2 锚点，与创意无冲突 |
| G3 机位数值 ±5%（硬） | **废除** | 改为**运镜语义软门**：VL 二值判读"镜头是否按 move_type 语义运动"（推近/横移/平摇/静止），判 FAIL 转人审。理由：LooseControlVideo 证明数值级逐帧控制是控制错位；CoaG 证明语义级轨迹跟随即可支撑成片 |
| G3b 帧数零误差（硬） | **保留** | A4 节拍锚点，成本为零且必须 |
| G4 VL 语义对照 ≥0.70（软门+打回） | **转职能** | 从"验收打回门"改为**抽卡选择器的意图符合度评分**（§3.3）。评分低不再自动打回白模——先看是不是 free 区的合法变奏；只有 locked 区违规才打回。阈值标定沿用 0.70 初值与独立基准（17 号草案 §5 对策 3 不变） |

### 3.3 抽卡多候选机制：N 候选 → VL 评分 → 人审兜底

**额度约束下的分层抽卡（核心成本设计）**——呼应冲刺计划 R1"迭代在本地、云端只定妆"：

```
第 1 层 · 草稿抽卡（本地，0 元，主力）
  每镜 N=3~4 候选：本地 LVACE（白模深度条件）或本地 t2v（自由模式）
  低分辨率短迭代，目的=出选题不出成片
第 2 层 · VL 自动评分（qwen3-vl-flash，1M token 池，每镜成本厘级）
  三维度打分 → 排序取 top-1（或 top-2 供人挑）
第 3 层 · 云端定妆（vace-plus 50 次池，只烧胜者）
  胜者候选 → 云端 720P 一次成片；关键结构主证镜（如 2-1 truck）允许 2 seed
第 4 层 · 人审兜底（老板/导演，每镜 ≤1 分钟）
  展示 top-2~3 候选缩略图，导演拍板或从备选池换人；可发起"再来一张"
```

**每镜 N 值建议与成本核算（A 档 9 镜口径）**：

| 项 | 数值 | 依据 |
|---|---|---|
| 本地候选 N | 3~4/镜（27~36 段） | 本地 0 元只花时间；GRANDMALEVIT 是 5 工具/镜、3-pass 社区实践是 6-12 draft/beat，3~4 是假期人力下的下限可用值（可无人值守跑） |
| VL 评分调用 | 每候选 1 次（抽 3 帧）≈ 每镜 3~4 次 | 17 号草案实测 VL 单次 1345 tokens；36 次 ≈ 5 万 tokens，占 1M 池 5%，**可忽略** |
| 云端 VACE 消耗 | 首轮 9~12 次（9 镜胜者 + 关键镜 ×2 + 重试 ≤6）≈ 15~18 次 / 50 池 | 比冲刺计划原预算（首轮 9-10+重试 6=16）持平或略增，**剩余 30+ 次给 B 档与对照实验** |
| 评分维度权重 | 意图符合度（locked 区合规）0.45 / 运动质量与动感 0.30 / 美感 0.15 / 结构无崩坏 0.10（一票否决项） | FIRM/VisionReward 实证：语义正确与物理合理权重应远大于主观美感（arXiv 2603.01509 权重表） |
| 人审接口 | 每镜卡片：top-3 缩略图+分数+一句话差异描述；导演动作=选/换/重抽/把变体收割为 proposed | GRANDMALEVIT"导演只做验收与择优"模式 |

**冲刺期简化**：若假期内本地抽卡产能不足，降级为 N=2（1 白模深度条件 + 1 自由 t2v 对照）——这个对照本身就在验证"约束 vs 自由"的哲学命题，产物直接回填本文档 §1.4。

### 3.4 白模可读性改进：解决"成片看不出是什么东西"

| 策略 | 做法 | 成本 | 评估 |
|---|---|---|---|
| **① ref image 配对（主推）** | 白模渲每镜 1 张代表性关键帧 + 分镜参考图（assets/storyboards/*.png 已有）一并喂 VACE `ref_images_url`；prompt 显式命名对象 | 0 元（云端接口原生支持，GitHub Wan2GP docs/VACE.md；本地 WanVideoVACEEncode 同样支持 ref_images，DeepWiki §13.4） | **性价比最高**：参考图直接告诉模型"这个方块是台灯"，与深度条件互补（深度管结构、ref 管语义）。风险：白模关键帧过抽象时 ref 可能被模型放大伪影——用分镜参考图为主、白模帧为辅双 ref 缓解（未验证，A 档首镜试点） |
| **② 逐几何体语义标注（必做，零成本）** | P2 产 scene_skeleton 时为每对象生成一句 prompt 语义（"画面左侧桌上一盏暖光台灯"）；自动拼进每镜 prompt 模板。object 命名规范（CHAR_/PROP_/SET_）已有，直接派生 | 0 元（契约字段） | VACE 官方明确建议"prompt 显式描述注入对象"；与 DyST-XL 实体级对齐同理。这是"接口决定创意流向"的正向应用 |
| **③ lineart 叠加（试点，不主力）** | 本地 IndexOB/Normal 派生线稿，与 depth 双条件或 control_condition=scribble | 本地可做；**云端 vace-plus 单 control_condition 槽位，depth 与 scribble 二选一**（comfy.icu 实测接口） | 评估：白模深度已够结构信号，线稿的增益主要在"边缘清晰度"（读得出物体轮廓）。云端不可双条件→只做本地 LVACE 试点；若 A 档某镜深度版读不出主体，该镜 fallback 试 scribble 档对比 |

三策组合建议：**② 立即全员做（改 P2 契约即可）+ ① A 档首镜试点后全量 + ③ 仅本地 fallback**。

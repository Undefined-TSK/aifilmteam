## 踩坑记录

### P1 档位改造 + 硬伤复核（2026-10-02）
- **问题**：D15/D16/D22/N13/N21 五项原为固定值（48 色/≤8/3s/50 步/≤60 节点），一刀切不适配项目规模差异
- **审计报告建议**：三档 24/48/96 色、≤4/≤8/≤16 对象、480p@2s/720p@4s/1080p@8s 健康线、30/100 步撤销、≤30/≤60/≤120 图规模
- **硬伤复核发现**：
  - D15"96 色”无明确场景依据（GRP 群演算 1 个的情况下，16 具名角色极罕见）
  - D22 线性时间 vs 像素非线性（5.2×像素比但只给 4×时间）
  - D16/N13/N21 依据充分，维持不变
- **修正结论**：
  - D15 改为 24/48/72 色（12 具名角色×6 备用比例）
  - D22 维持 2s/4s/8s（含工程缓冲系数≈1.5×理论像素值）
  - D16/N13/N21 维持原建议
- **关键发现**：改造只动档位配置层，不改机制；档位设计原则=2-4 档、档间差异明显（3×/10×跨度）、场景对应清晰

### 白模定位澄清（2026-10-02）
- **问题**：白模是首帧参考图还是整段动画视频
- **结论**：整段动画视频喂引擎
- **影响**：17 处修正，新增 D6b/D25 决策
- **关键发现**：本机 Blender 构建无 FFmpeg 能力，必须外部打包

### 帧率错位问题
- Wan 3.0 输出固定 30fps，白模母版 24fps
- 解决方案：时长为准，帧数按帧率派生 8k+1

### 全局反思 A6b 三分法粗糙（2026-10-02）
- **问题**：原"A6b 三分法”（创作文脑/执行工脑/人工事脑）过于笼统，没有考虑同一岗位在不同任务上用不同的脑
- **修正方案**：升级为“岗位×任务类型”两层矩阵
- **连带发现的其他孤立问题**：A4/A5/A8/A12/A14/A25/A26 都需要结合更多维度看，不能单维度定档
- **关键发现**：没有岗位是单一用脑类型——必须拆解到"任务粒度”分配模型档次

## 方法论沉淀

### 一刀切判断原则
1. 问「有没有场景需要不同的值？」→ 有则需要分档
2. 问「这个值是技术约束还是设计选择？」→ 设计选择可分档
3. 问「当前阶段是否需要立即分档？」→ 否则 D 类待后评
4. 问「分档后配置成本是否高于收益？」→ 过度分档也是问题

### 档位设计原则
1. 2-4 档为宜，不是越多越好
2. 档位之间有明显差异（如 3×或 10×的跨度）
3. 档位有清晰的场景对应（用户能判断该选哪档）
4. 默认档是最常用场景，减少用户决策负担

### 全局反思六维度检查法
1. 要做什么：这个决策要解决什么具体问题？
2. 职责：谁负责执行/检查/验收？
3. 工具：依赖什么技术/API/系统？
4. 流程位置：在哪个阶段被消费？阻塞哪些下游？
5. 与其他 AI 关系：如何与其他岗位的 Agent 协作？
6. 团队关系：如何在 CrewAI Flows 中编排？失败如何处理？

**核心原则**：不孤立看任何一个决策点——必须放到**任务×岗位矩阵**和**流程依赖链**中检验。

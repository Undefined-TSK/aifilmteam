## 4. 验证结论：配齐装备后，这两个问题是否自然消失

### 4.1 机理层论证

**画面黑——是的，机理上消失。** 黑的物理本质是曝光方程无解（§1 A3）：室内+窗口单进光口+环境光≈0+EEVEE 无 GI。解该方程需要的算子是明确的：set_world 给环境光底座（哪怕 studio_gray 0.3 就能整体抬亮）、update_light 把 350W 改到 1500W 而不必弃灯新建、delete_object 清理废灯避免光路混乱、定量亮度反馈把"盲猜 350→1200→1500"的三轮试错压成一轮测光修正。LLM 第 6/8 轮的诊断（遮挡+能量 350）证明它**知道解是什么**，只是没有算子可执行。装备补齐后，"解存在且可执行"，问题在机理上不再出现。

**运镜过头——是，但需要一个前提。** 过头的本质是开环控制（§2）：初版 0.37m/2.7 倍超画幅是几何必然；修好不是靠模型更聪明，是靠**闭合反馈回路**——防怼脸护栏（最小距离 = f(焦段, 主体尺寸) 事前算出）把致命距离拦在打帧之前，VL 强制重渲+末帧必渲把"评旧图/看不见末段"两个断点焊死。Scene-Level Generation 综述的消融实验（去掉反馈→空间一致性大幅下降）与 Thinking in Blender 的照明迭代回路分别从正反两面证实：**反馈回路在场，同级模型表现合格；反馈缺场，同级模型必然翻车**。前提：护栏阈值需试点标定（17c §3.2 同款"未验证，试点标定"原则）。

### 4.2 置信度与待实证标注

- **本结论 = 机理判定 + 日志实证（v1 反面证据充分）+ 待 v2 正面确认。**
- R17-9-3 修复轮正在重跑 1-2 镜（set_world 已入 addon、护栏在途、VL 降级"参考+人审兜底"R17-9-1、max_tokens≥6144）。**v1/v2 对比数据（VL 通过轮数、preview 重渲次数、末帧距离、亮度均值）回来后，本文 §4 结论自动升级为实证**——建议对比指标就按前述四项采集，与 pilot_summary.json 字段对齐。
- 修复轮未覆盖的两项（update_light、delete_object）建议在 v2 出数据后优先补入下一轮，属低成本高杠杆（各≈20 行 handler）。

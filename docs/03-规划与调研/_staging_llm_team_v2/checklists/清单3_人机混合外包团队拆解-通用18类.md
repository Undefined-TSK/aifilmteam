# 清单三：人机混合外包团队拆解（通用 18 大类版）

> 来源：老板 2026-10-04 送达原文（逐字保留）。用途：LLM 团队构建·四维深度版系统调研·任务六逐条对照检查表（框架参照）。

可以。下面把它当成一个"人机混合外包团队"来拆：**你（人类负责人）+ 多个 LLM/LM Agent + Skills 技能包 + MCP 连接器 + 外部 API/SaaS/外包供应商 + 编排/记忆/评估/安全/运维层**。
先说明：你说的 LL、LM，我统一理解为语言模型/大模型及其不同角色实例；MCP 指 Model Context Protocol；Skills 指可被调用的技能/工具包。

要跑通全流程，不只是"模型能不能回答"，而是**目标、角色、协议、上下文、权限、质量、安全、成本、责任、失败恢复**全都要考虑。下面尽量罗列细。

## 一、先定义团队与全流程

### 1. 团队拓扑问题
- 你是什么角色：产品负责人、审批人、仲裁者、客户接口、最终责任人？
- LLM 是员工、工具、外包商、顾问，还是代理？法律和责任身份是什么？
- 多个 LLM 是否分角色：PM、架构、开发、测试、运维、研究、审查、法务、财务？
- Skills 是能力还是员工？谁拥有、谁维护、谁审批？
- MCP 是通道还是权限边界？连接哪些外部系统？
- 外部外包工具是 API、SaaS、RPA、自由职业者还是供应商团队？
- 谁有最终决策权：你、某个 LLM、投票、仲裁器、客户？
- 团队边界：哪些事内部做，哪些外包，哪些禁止？
- 成功标准：交付物、时间、成本、质量、安全、合规。
- 失败标准：什么情况必须停机、回滚、人工接管？

### 2. 全流程阶段
- 需求收集：用户故事、验收标准、隐含需求、利益相关者。
- 规划：任务分解、依赖、优先级、估算、资源、预算。
- 设计：架构、接口、数据流、权限、协议、状态。
- 开发：代码、文档、配置、提示词、技能、MCP server。
- 数据：采集、清洗、标注、版本、隐私、权限。
- 集成：LLM 接 Skills，Skills 接 MCP，MCP 接外部工具。
- 执行：编排、调度、并发、重试、人工审批、异常处理。
- 验证：单元、集成、E2E、事实核查、红队、人审。
- 交付：部署、发布、文档、培训、客户验收。
- 运维：监控、告警、日志、追踪、成本、SLA。
- 反馈：用户反馈、度量、回归、迭代。
- 退役：数据清理、权限回收、版本归档、供应商退出。

## 二、LLM/LM 自身要考虑的问题

- 幻觉：编造事实、引用、API、代码、法律条款。
- 事实性：知识截止、时效、来源可信度。
- 推理：长链推理错误、跳步、自相矛盾。
- 规划：任务分解不合理、遗漏依赖、优先级错误。
- 上下文窗口：溢出、遗忘、注意力稀释、中间丢失。
- 摘要失真：多次压缩后关键信息丢失。
- 指令遵循：不按格式、不按约束、忽略否定指令。
- 工具选择：该调工具不调，或乱调、重复调。
- 参数错误：API 参数、SQL、代码、配置写错。
- 不确定性表达：不会说"不知道"，过度自信。
- 校准：置信度与实际正确率不匹配。
- 偏见：性别、种族、地域、文化、政治、商业偏见。
- 毒性：攻击性、歧视、不当内容。
- 安全对齐：越狱、提示注入、角色扮演绕过。
- 记忆：短期/长期记忆混乱，记住不该记的。
- 隐私：泄露训练数据、上下文、密钥、客户数据。
- 多语言：小语种、混合语言、翻译失真。
- 领域适应：医疗、法律、金融、工业等专业错误。
- 代码能力：可运行但错误、安全漏洞、依赖冲突。
- 数学：计算错误、单位错误、统计误用。
- 多模态：图、表、PDF、音频理解错误。
- 随机性：温度导致不可复现。
- 版本漂移：模型升级后行为变化。
- 成本：token、API、推理延迟。
- 延迟：首 token、总时长、并发。
- 吞吐：限流、配额、队列。
- 自我批评：自我审查不可靠，越改越错。
- 目标漂移：执行中偏离原始目标。
- 奖励黑客：为指标优化而损害真实目标。
- 能力边界：不知道自己不能做什么。
- 模型选择：开源/闭源、大小、专用/通用、本地/云。
- 微调/RAG/提示工程：哪种手段解决哪类问题。
- 评估：基准分数与真实业务差距。

## 三、Skills 技能包自身要考虑的问题

- 定义：每个 skill 解决什么问题，不解决什么问题。
- 粒度：太粗难复用，太细调用爆炸。
- 组合：多个 skill 如何串联、并联、条件分支。
- 依赖：skill 依赖哪些库、API、数据、权限。
- 输入输出 schema：字段、类型、必填、枚举、示例。
- 版本：v1/v2 兼容，旧调用是否失效。
- 兼容性：不同 LLM、MCP、平台是否支持。
- 权限：能读什么、写什么、删什么、发给谁。
- 认证：API key、OAuth、token、证书、轮换。
- 密钥管理：不能进提示词、日志、代码库。
- 错误处理：超时、限流、500、部分成功。
- 重试：指数退避、最大次数、幂等。
- 幂等：重复调用是否重复扣款、重复发消息。
- 超时：短任务/长任务、异步、回调。
- 限流：QPS、并发、日配额。
- 发现：LLM 怎么知道有哪些 skill。
- 路由：哪个 skill 最适合当前任务。
- 冲突：多个 skill 功能重叠时选哪个。
- 测试：单元、契约、模拟、沙箱。
- 文档：描述、示例、边界、失败案例。
- 安全：代码执行、文件系统、网络访问。
- 隐私：发送到外部前是否脱敏。
- 成本：每次调用费用、缓存。
- 可观测：日志、追踪、指标、审计。
- 更新：谁发布、谁审批、谁回滚。
- 弃用：旧 skill 如何下线。
- 跨平台：MCP、OpenAPI、函数调用、插件。
- 状态：无状态还是有状态，状态存哪。
- 结果验证：skill 返回结果是否可信。
- 降级：失败后有无替代方案。
- 人审：哪些 skill 必须人工确认。

## 四、MCP 连接器自身要考虑的问题

- 协议版本：MCP 版本兼容。
- Server 发现：怎么注册、发现、选择。
- 路由：请求发给哪个 server。
- 认证：OAuth、API key、mTLS、SSO。
- 授权：最小权限、角色、租户隔离。
- 资源：文件、数据库、知识库、网页。
- 工具：函数、API、命令、工作流。
- 提示模板：是否可被恶意篡改。
- 传输：stdio、SSE、HTTP、WebSocket。
- 会话：会话保持、超时、恢复。
- 状态：有状态 server 的并发问题。
- 供应链：第三方 server 是否可信。
- 恶意 server：返回注入内容、窃取数据。
- 提示注入：工具描述、返回内容污染 LLM。
- 数据边界：哪些数据不能出本地/租户。
- 租户隔离：多客户是否串数据。
- 审计：谁调了什么、何时、结果。
- 速率限制：server 端限流。
- 错误语义：错误码是否统一。
- 重试：幂等与重试安全。
- 超时：长任务、异步任务。
- 本地/远程：本地权限高但难管理，远程方便但隐私风险。
- 多 server 冲突：同名工具、权限冲突。
- 工具描述质量：描述差导致 LLM 选错。
- 动态工具列表：运行时变化如何通知。
- 成本：调用费、流量费、云费。
- 延迟：跨网、跨区。
- 升级：协议升级、server 升级。
- 测试：模拟 server、契约测试。
- 可观测：追踪跨 server 调用链。
- 合规：数据跨境、行业法规。

## 五、记忆、上下文与 RAG

- 短期记忆：当前对话、任务状态。
- 长期记忆：用户偏好、项目知识、历史决策。
- 共享记忆：多个 LLM 是否共享，共享什么。
- 私有记忆：每个 agent 是否隔离。
- 写入策略：谁写、何时写、写什么。
- 读取策略：谁读、读多少、优先级。
- 遗忘：过期、删除、用户要求删除。
- 压缩：摘要、滚动窗口、关键帧。
- 检索精度：召回不准导致错误。
- 召回：该找的没找到。
- 切分：文档切分粒度。
- 嵌入：模型选择、维度、更新。
- 向量库：性能、成本、权限、备份。
- 元数据：来源、时间、权限、版本。
- 污染：错误信息进入长期记忆。
- 过时：旧政策、旧价格、旧 API。
- 冲突：多个来源矛盾。
- 引用：必须能溯源。
- 隐私：记忆里不能有密钥、PII。
- 删除：GDPR/CCPA 删除请求。
- 审计：谁写过、谁读过。
- 缓存：缓存失效、脏读。
- 一致性：多 agent 看到不同上下文。
- 成本：长上下文 token 费。
- 多 agent 同步：黑板、事件、消息。

## 六、编排与多智能体系统

- 角色定义：每个 agent 的职责、边界、权限。
- 目标对齐：全局目标 vs 局部目标。
- 任务分解：谁拆、拆多细、怎么验收。
- 依赖管理：前置、后置、并行、阻塞。
- 优先级：紧急/重要、客户/内部。
- 调度：谁先做、谁等待、谁抢占。
- 并发：并发写冲突、资源竞争。
- 串行：串行太长、瓶颈。
- 死锁：互相等待。
- 循环：无限对话、无限调用。
- 重复：多个 agent 做同一件事。
- 负载：任务分配不均。
- 能力路由：任务给最合适的 LLM/skill。
- 状态机：任务状态、转换条件。
- 检查点：中断后恢复。
- 恢复：失败重试、补偿。
- 人审：关键节点人工确认。
- 升级：异常升级路径。
- 仲裁：冲突谁拍板。
- 投票：多数决、加权、否决权。
- 共识：达成一致的成本。
- 预算：token、时间、金钱、API 配额。
- 超时：全局和局部超时。
- 终止条件：什么时候算完成。
- 通信协议：消息格式、语义、版本。
- 共享黑板：公共状态。
- 事件总线：异步事件。
- 可观测：跨 agent 追踪。
- 评估：多 agent 整体评估。

## 七、LLM 与 LLM 之间的问题

- 角色重叠：两个 agent 都以为自己做 PM。
- 边界不清：谁决定、谁执行、谁审查。
- 上下文不一致：各自看到不同信息。
- 信息丢失：交接时漏关键约束。
- 幻觉传播：一个编，另一个当真并放大。
- 错误放大：小错滚成大错。
- 协议不统一：消息格式、字段、语义不一致。
- 消息格式：JSON、自然语言、混合。
- 决策权：谁有最终决定权。
- 冲突仲裁：意见冲突怎么解决。
- 循环依赖：A 等 B，B 等 A。
- 无限对话：互相感谢、反复确认。
- 死锁：都等对方先动。
- 成本爆炸：多 agent 对话烧 token。
- token 竞争：上下文窗口被废话占满。
- 串扰：A 的上下文污染 B。
- 污染：错误记忆共享。
- 偏见放大：群体极化。
- 记忆共享/隔离：该共享的没共享，不该共享的共享了。
- 版本不一致：不同模型、提示、技能版本。
- 安全注入：一个被注入，传染其他。
- 责任归属：错误由哪个 agent 负责。
- 评估难：多 agent 功劳/责任难分。
- 通信延迟：同步等待。
- 工具权限不同：同样任务结果不同。
- 目标漂移：各自优化局部目标。
- 重复劳动：重复搜索、重复写代码。
- 格式不一致：交付物风格不统一。
- 隐含上下文：默认对方知道，其实不知道。
- 能力不对称：强模型看不起弱模型输出。
- 上下文窗口：长对话截断。
- 知识截止：不同模型知识新旧不同。
- 温度随机：不可复现。
- 信任：是否信任对方输出。
- 欺骗：agent 为达标虚报。
- 合谋：多个 agent 一起绕过规则。
- 竞争：抢资源、抢权限。
- 可解释：为什么得出这个结论。

## 八、LLM 与人类/团队之间的问题

- 指令模糊：你一句话，LLM 理解成十种。
- 误解：领域黑话、缩写、隐含前提。
- 澄清：该问不问，或问太多。
- 自动化偏见：你过度信任 LLM。
- 过度信任：不检查直接发布。
- 权限边界：LLM 能做什么，不能做什么。
- 审批点：哪些必须你签字。
- 人在环：人在环还是人在回路。
- 责任法律：出错谁负责。
- 沟通界面：聊天、看板、PR、工单、邮件。
- 任务分配：LLM 接单、拒单、转单。
- 汇报：进度、风险、阻塞。
- 升级：什么时候找你。
- 绩效：怎么考核 LLM/skill。
- 隐性知识：你脑子里的经验难传递。
- 文化：团队文化、语言、时区。
- 信任：你信不信，LLM 信不信你。
- 心理安全：出错是否敢报。
- 变更管理：你抗拒或依赖。
- 培训：你需要会提示、审查、调试。
- 提示：你怎么写提示。
- 审查：你怎么验结果。
- 调试：出错怎么定位。
- 会议：LLM 是否参会。
- 同步：每日站会、周报。
- 上下文共享：你的记忆 vs 系统记忆。
- 冲突解决：你仲裁还是投票。
- 社会工程：你被 LLM 或外部工具骗。
- 提示注入：外部内容操纵 LLM 再影响你。
- 伦理：LLM 建议影响你的决策。
- 控制：你能否暂停、回滚、接管。
- 解释：LLM 能否解释理由。
- 可撤销：错误操作能否撤销。
- 用户体验：等待、焦虑、不确定。
- 过度依赖：你能力退化。
- 责任分散：大家都以为别人负责。

## 九、人类团队/组织自身的问题

- 目标：到底要什么。
- 范围：做什么，不做什么。
- 成功标准：可量化验收。
- 角色：谁负责什么。
- 架构：汇报线、指挥线。
- 沟通：频率、渠道、格式。
- 决策：谁拍板、多久拍板。
- 任务分配：公平、能力匹配。
- 记忆：组织记忆、项目记忆。
- 冲突：利益、优先级、资源。
- 绩效：KPI、OKR、考核。
- 激励：奖励什么，惩罚什么。
- 信任：跨部门、跨供应商。
- 透明：信息是否公开。
- 责任：RACI 矩阵。
- 法律：合同、主体、责任。
- 文化：冒险、保守、创新。
- 培训：AI 素养、安全、合规。
- 变更：流程、工具、模型变更。
- 供应商：SLA、合同、退出。
- 预算：人力、API、云、外包。
- 合规：行业、地区、公司政策。
- 伦理：AI 使用伦理。
- 安全：内部威胁、外部攻击。
- 灾备：关键人依赖、供应商故障。
- 知识：文档、Wiki、交接。
- 会议：太多/太少。
- 文档：谁写、谁更新。
- 版本：流程版本、工具版本。
- 入职/离职：权限、知识。
- 扩展：从 1 个项目到多项目。
- 多租户：多客户隔离。
- 政治：权力、信息不对称。
- 信息不对称：你知道的 LLM 不知道。

## 十、外部外包工具/供应商问题

- API 稳定性：版本、弃用、变更。
- SLA：可用性、响应、赔偿。
- 限流：QPS、日配额。
- 计费：按次、按量、隐藏费。
- 认证：key、OAuth、证书。
- 密钥：存储、轮换、泄露。
- 数据隐私：数据是否被训练。
- 跨境：数据出境。
- 合规：GDPR、SOC2、HIPAA。
- 审计：能否审计供应商。
- 供应商锁定：迁移成本。
- 退出策略：怎么换。
- 文档：是否完整。
- 支持：工单、响应时间。
- 故障：宕机、降级。
- 依赖：下游依赖链。
- 供应链：第三方库、开源漏洞。
- 安全：恶意供应商、被黑。
- 质量：返回数据准不准。
- 成本：总拥有成本。
- 合同：责任、保险、保密。
- 沟通：时区、语言、文化。
- 知识产权：产出归谁。
- 保密：NDA。
- 竞争：供应商是否服务对手。
- 灾难：供应商倒闭。

## 十一、安全、合规、伦理

- 提示注入：直接、间接、工具返回。
- 越狱：绕过安全策略。
- 数据泄露：密钥、PII、客户数据。
- 供应链攻击：恶意 MCP server、skill、库。
- 权限提升：低权限 agent 拿到高权限。
- 工具滥用：发邮件、删库、转账。
- 密钥管理：不进提示、日志、代码。
- 隐私：最小化、脱敏、加密。
- 合规：GDPR、CCPA、AI Act、行业法规。
- 审计：谁做了什么。
- 可解释：为什么做这个决定。
- 公平：偏见、歧视。
- 毒性：有害内容。
- 版权：训练数据、生成内容。
- 许可：开源许可证。
- 出口管制：模型、加密。
- 责任：AI 出错谁赔。
- 伦理：人类监督、可撤销。
- 红队：对抗测试。
- 事件响应：泄露、滥用、停机。

## 十二、质量与评估

- 基准：通用基准 vs 业务基准。
- 真实业务：黄金集、历史案例。
- A/B：新旧版本对比。
- 人工：专家评审。
- 自动：规则、模型评审。
- 对抗：红队、注入。
- 回归：新版本是否破坏旧功能。
- 漂移：数据、模型、用户行为漂移。
- 事实核查：引用、来源。
- 代码测试：单元、集成、安全。
- 性能：延迟、吞吐。
- 用户体验：满意度、信任。
- 验收标准：可测。
- 评分：多维、加权。
- 校准：置信度。
- 可解释：理由链。
- 审计：可追溯。

## 十三、可观测性与运维

- 日志：提示、响应、工具调用。
- 指标：token、成本、延迟、错误率。
- 追踪：跨 agent、跨 MCP、跨 API。
- 决策路径：为什么选这个 skill。
- 告警：异常、成本、安全。
- SLA：可用性、响应。
- 事故：分级、响应、复盘。
- 回滚：模型、提示、技能、配置。
- 灾备：备份、恢复。
- 容量：并发、队列。
- 缓存：命中率、失效。
- 死信：失败任务。
- 重试：策略、幂等。
- 降级：降级方案。
- 熔断：防止雪崩。
- 限流：保护下游。
- 版本：配置、密钥轮换。
- 权限回收：离职、项目结束。

## 十四、成本、性能与经济

- token 成本：输入、输出、缓存。
- API 成本：外部调用。
- 云成本：计算、存储、流量。
- 人力成本：你、专家、外包。
- 机会成本：做这个不做那个。
- 延迟：用户等待。
- 吞吐：并发任务。
- 上下文：长上下文贵。
- 缓存：省钱但可能脏。
- 模型选择：大模型贵但准，小模型便宜但弱。
- 蒸馏/量化：性能损失。
- 批处理：延迟换成本。
- 路由：简单任务给小模型。
- 预算：硬上限、软上限。
- ROI：投入产出。
- 计费：成本归属到项目/客户。
- 优化：持续降本。

## 十五、版本、变更与配置

- 模型版本：升级、回滚。
- 提示版本：A/B、回归。
- 技能版本：兼容、弃用。
- MCP 版本：协议、server。
- 数据版本：训练、RAG、评估。
- 代码版本：Git、分支、发布。
- 配置版本：环境、参数。
- 环境：开发、测试、生产。
- 依赖：库、API、模型。
- 迁移：数据、权限、记忆。
- 兼容：旧调用是否可用。
- 回滚：一键回滚。
- 灰度：小流量。
- 审计：谁改了什么。
- 变更管理：审批、通知。
- 文档：更新。

## 十六、失败模式与恢复

- 幻觉：事实错误。
- 工具失败：API 宕机。
- 超时：任务卡住。
- 限流：被下游拒绝。
- 认证失败：key 过期。
- 数据错误：脏数据。
- 权限拒绝：越权。
- 部分成功：一半成一半败。
- 重复执行：重复下单、发信。
- 状态丢失：上下文丢失。
- 上下文溢出：截断。
- 死锁：互相等。
- 无限循环：烧钱。
- 成本爆炸：预算超。
- 安全事件：泄露、注入。
- 供应商故障：外部挂。
- 模型漂移：行为变。
- 人为错误：你点错。
- 恢复策略：检查点、补偿、人工接管。

## 十七、度量与治理

- KPI：质量、速度、成本、安全、合规、满意度。
- 治理：政策、审批、责任、审计。
- 伦理委员会：谁审。
- 红队：定期对抗。
- 事件：分级、响应。
- 供应商：准入、评估、退出。
- 数据：分类、分级、权限。
- 模型：准入、评估、监控。
- 工具：准入、权限、审计。
- 责任：RACI。
- 报告：向谁汇报。
- 改进：复盘、迭代。

## 十八、最小跑通检查表

如果先跑通一个 MVP，至少回答：

1. 一个端到端用例是什么？
2. 成功验收标准是什么？
3. 你、LLM、skill、MCP、外部工具各自角色？
4. 谁有最终决策权？
5. 哪些操作必须人工审批？
6. 用哪个编排器？
7. 接哪 1-2 个 MCP server？
8. 定义哪 3-5 个核心 skills？
9. 每个 skill 的输入输出、权限、错误处理？
10. 记忆放哪，共享还是隔离？
11. 上下文怎么压缩和检索？
12. LLM 之间怎么通信，格式是什么？
13. 冲突怎么仲裁？
14. 失败怎么重试、回滚、人工接管？
15. 成本怎么算，预算多少？
16. 日志、追踪、审计怎么做？
17. 安全红队怎么测？
18. 数据隐私和合规边界？
19. 版本怎么管理？
20. 怎么评估质量？
21. 怎么收集反馈迭代？
22. 怎么退出供应商/下线技能？
23. 谁负责法律和责任？
24. 灾备和关键人依赖？
25. 什么时候停机？

---

最致命的问题通常不是"模型不够强"，而是：**目标不清、权限不清、责任不清、上下文不一致、LLM 之间冲突、工具失败无恢复、安全无边界、成本无上限、评估无标准、人类过度信任**。
建议先做一个窄场景、短流程、强人审、可回滚的 MVP，再逐步加 LLM、skills、MCP 和外包工具。

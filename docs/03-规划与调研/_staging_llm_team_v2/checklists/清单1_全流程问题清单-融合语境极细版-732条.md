# 清单一：人机混合外包团队全流程问题清单（融合项目语境 · 极细版）

> 来源：老板 2026-10-04 送达原文（逐字保留）。用途：LLM 团队构建·四维深度版系统调研·任务六逐条对照检查表。
> 团队构成：你（人类负责人）+ 多个 LLM/LM Agent + Skills 技能包 + MCP 连接器 + 外部 API/SaaS/外包供应商 + 编排/记忆/评估/安全/运维层。
> LL/LM 统一理解为语言模型/大模型及其不同角色实例；MCP 指 Model Context Protocol；Skills 指可被调用的技能/工具包。
> 要跑通全流程，不只是"模型能不能回答"，而是目标、角色、协议、上下文、权限、质量、安全、成本、责任、失败恢复全都要考虑。
> 本文按 24 大类展开，尽量挂项目真实名词：五操作员 N1–N5、7+2 旧岗、crew_bus、registry、intent_graph、layer manifest、VACE、qwen3-vl-flash、vram_lock、cost_ledger、quota_gate、approval_service、handoff_package、operator_card、R0~R6、D/N/A/T/C/G/B/P/SC/RC/PH 系列决策。

## 〇、先定义团队与全流程

### 0.1 团队拓扑
1. 你是什么角色：产品负责人、审批人、仲裁者、客户接口、最终责任人？
2. LLM 是员工、工具、外包商、顾问，还是代理？法律与责任身份是什么？
3. 多个 LLM 是否分角色：N1 意图理解 / N2 白模搭建 / N3 控制图派生 / N4 云端重绘 / N5 配音配乐剪辑？
4. 旧 7+2 岗（导演/制片/编剧/预演/白模/写实化/场记 + 音效师/剪辑师）与 N1–N5 怎么映射？
5. Skills 是能力还是员工？谁拥有、谁维护、谁审批？
6. MCP 是通道还是权限边界？连接哪些外部系统？
7. 外部外包工具是 API、SaaS、RPA、自由职业者，还是供应商团队？
8. 谁有最终决策权：你、导演岗、制片岗、投票、仲裁器、客户？
9. 团队边界：哪些事内部做，哪些外包，哪些禁止？
10. 成功标准：交付物、时间、成本、质量、安全、合规。
11. 失败标准：什么情况必须停机、回滚、人工接管？
12. 老板「全走推荐」授权后，你的实际介入边界在哪？
13. 三介入门（三档位指令 / 锚点签收 / 人审卡片）之外，是否真的不介入？
14. 导演集中式决策 vs 制片熔断裁决，谁优先？
15. 场记 QC vs 写实化岗归因，谁定责？

### 0.2 全流程阶段
16. 需求收集：用户故事、验收标准、隐含需求、利益相关者。
17. 规划：任务分解、依赖、优先级、估算、资源、预算。
18. 设计：架构、接口、数据流、权限、协议、状态。
19. 开发：代码、文档、配置、提示词、技能、MCP server。
20. 数据：采集、清洗、标注、版本、隐私、权限。
21. 集成：LLM 接 Skills，Skills 接 MCP，MCP 接外部工具。
22. 执行：编排、调度、并发、重试、人工审批、异常处理。
23. 验证：单元、集成、E2E、事实核查、红队、人审。
24. 交付：部署、发布、文档、培训、客户验收。
25. 运维：监控、告警、日志、追踪、成本、SLA。
26. 反馈：用户反馈、度量、回归、迭代。
27. 退役：数据清理、权限回收、版本归档、供应商退出。
28. 你的项目把全流程切成 R0~R6，每阶段签字，是否每阶段都有对应 LLM/Skills/MCP 能力？
29. R0 盘点 → R1 需求 → R2 调研 → R3 架构 → R4 技术验证 → R5 样片 → R6 平台，当前卡在 R4，谁负责推进？

## 十九、最终结论

最致命的问题通常不是"模型不够强"，而是：
- 目标不清
- 权限不清
- 责任不清
- 上下文不一致
- LLM 之间冲突
- 工具失败无恢复
- 安全无边界
- 成本无上限
- 评估无标准
- 人类过度信任

建议先做一个窄场景、短流程、强人审、可回滚的 MVP：
**1-2 镜白模 → 本地 VACE → VL 自检 → 人审卡片 → 写实化 → QC 报告**
再逐步加 MCP、skills、云端引擎和外包工具。

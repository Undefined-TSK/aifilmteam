### 2.2 与 QC 环节的用法（替代 LLM-as-Judge 主观打分）

- **现有 QC 痛点**：S1 §三 将云端 VL 判读定为"语义级辅助审阅，输出仅作参考不入五项硬指标"；R17-8a 试点 VL 4 轮全否决、R17-9-1 已裁定 VL 降级"参考+人审兜底"——根因之一是 LLM-as-Judge 打分主观、不稳定、无概率语义。
- **决策模型对症点**：
  1. **崩坏否决 = noul（是非）**：单帧"是否穿帮/是否崩坏"返回概率分布而非自由文本，可量化设阈值；
  2. **构图/动感评分 = score**：返回分数 + 置信度，置信度低的分数自动降为"建议级"——与 R17-9-1 "参考级不阻塞"定位天然吻合；
  3. **镜头类型分流 = choice**：逐帧分类（全景/中景/特写）用于 QC 报表与分镜对账；
  4. **批量逐帧校验**：RPM 1200 / TPM 2M 的高限流 + 恒定延迟，适合 72 帧/镜的批量逐帧判定，成本远低于生成式 judge（不产 token）。
- **接入注意**：独立 systemone 协议需单独写适配器（不能复用现有 OpenAI 兼容 client）；预览版模型存在变更/下线风险，生产依赖前须评估。
- **结论**：列为 **QC 链候选 P1 试点项**——先在 VL 复审环节用小样本对照 qwen3-vl-flash 主观打分，验证置信度阈值可行性，再决定是否常驻。

## 7. 遗留项补查（一箭双雕）

### 7.1 GLM-5-Turbo "专门为 Agent 场景优化"说法

- **结论：说法成立，有官方发布口径**。2026-03-16 智谱发布 GLM-5-Turbo，官方定位"**全球首个面向 OpenClaw（龙虾）场景深度优化的基座模型**"——OpenClaw 即 Agent 场景。官方明列四大专项增强：① 工具调用（外部工具与 Skills 调用不掉链子）；② 指令遵循（复杂多层/长链路指令拆解，多智能体协同）；③ 定时与持续性任务；④ 高吞吐长链路执行。并发布自研 Agent 评测基准 **ZClawBench**（GLM-5-Turbo 国产模型第一）。
- **官方出处**：智谱官方微信公众号发布稿（搜狐/网易/证券时报转载：https://www.sohu.com/a/997074892_120988533 、https://www.163.com/dy/article/KO55L7O0053469RG.html 、https://www.stcn.com/article/detail/3678512.html ，查询日 2026-10-04）。

- **对项目含义**：N2 MCP 操控需要"工具调用+长链路稳定"，GLM-5-Turbo 的官方能力画像对口；但百炼无额度、直连更贵、台账内 glm-5.3（行 74）已实测可用——暂不引入，仅存档选型依据。

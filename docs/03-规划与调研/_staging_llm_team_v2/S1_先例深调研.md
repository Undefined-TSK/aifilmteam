### 1.3 LIRA/CINEDANCE/ACTING 真实出处：Higgsfield《The Cully Hill Boys》——公开材料中工业级最强的"提示词纪律"实证

官方口径（自报，无第三方审计）：
- **规模**：1:54:53（对外称 110 分钟）；137 场；600 个已锁定资产；~150 个命名锁（其中 ~80 个后缀 "= discard"）；总成本 $2M（约一半 $1M 为算力）；4 周工期；28 人（其中 9 名导演）；100% 纯生成（无实景无摄制组，唯一例外一场追车戏实拍一天手机素材作运动参考）。
- **版本纪律**：版本日志 137 条，最难镜头打到 v15/v10/v9；**镜头卡编号（如 50B/50C）从卡片→版本日志→prompt 文件全程同 ID 贯穿**。
- **五工具分工**：Seedance（全部镜头/视频/声音）、Soul Cinema（面部/角色表）、Seedream + Nano Banana（剪辑/视点切换）、Claude（写全部提示词，**图/视频分两个独立聊天室，防两套规则串扰**）、音乐 Suno。
- **三个公开 SKILL.md**（CloudFront 直链可下载）：
  1. **LIRA**（图像提示词）：内置**各图像模型弱点自检清单**（哪些词会召唤片场、哪些光源会被烤进画面、哪个模型总丢哪些细节），发送前自检；
  2. **CINEDANCE**（视频提示词三层）：**writer**（拆解走位/光学/物理/时序）→ **reviewer**（发送前复检空首帧/过期标签/弱空间关系/自相矛盾行）→ **workbench**（prompt 落文件，**失败只补丁该段、永不整篇重写**）；
  3. **ACTING**（表演系统提示词）：**行为优于情绪**；面部/身体逐拍增量书写，拒绝形容词；角色行为档案格式。
- **四条从上部片（HELL GRIND）带来的铁律**：①每镜头开头声明剧情语境+在场者+时长；②首帧空间锁（第一帧全员就位，无空镜起手）；③**每句台词后留 1 秒静音尾巴**（给剪辑留缝、让模型没空间编造声音）；④表演逐拍书写。
- **方法论内核**："模型没有记忆，一致性就是全部工作"；**每个镜头 = reference + text 双输入**（资产管外观，文本管其余一切**包括几何**：谁站哪、相机在哪侧、光从哪来）；**资产锁死才开工**（先 10+ 种动作/环境压测角色资产，通过的才进正片）；**状态即资产**（干净夹克 Cal / 落水湿身 Cal / 三幕带伤 Cal 是三个资产而非一个资产加备注；资产构成：74 主角反派卡 + 52 配角动物卡 + 90 一两场背景卡 + 159 道具 + 200+ 场景底图）；**10–15 次仍失败→拆解/简化场景本身，而不是继续改措辞**。
- **路线差异（重要，勿盲从）**：该片全程**纯 text-to-video、不用首帧图/不用图生视频**——理由是纯 t2v 的镜头之间反而更好剪。这与我们"白模→控制图→VACE 重绘"路线**取向相反**（我们要可控性，他们要剪辑连贯性），两者各有成立边界，不构成对我们路线的否证；他们唯一的失控案例（车内两人近身夺枪，肢体缠绕、枪在手间消失）恰是**近身持续接触**场景——这类场景我们走 Blender 白模摆位+控制图反而更稳。

  - 英文评述（团队 28 人/9 导演/$1M 算力/工具链构成）：https://metallab.ai/en/2026/8/we-made-the-first-110-minute-ai-feature-film-with-a-real-cast-the-cully

### 1.4 "Méliès 技法库"真实形态：melies.co 商业产品，424 种（非 380）

- **是什么**：melies.co（一体化 AI 影视制作 SaaS，与 ai-film-pipeline 仓库无关）公开的 **Cinematic Techniques 在线技法库：424 种技法、13 类目**——运镜 86 / 实拍光学特效 57 / 病毒风 44 / 灯光 41 / 构图 32 / 类型风 27 / 景别 25 / 剪辑转场 23 / 时间运动 21 / 机位 19 / 色彩胶片感 19 / 镜头光学 17 / 氛围天气 13。
- **卡片结构**（每条技法统一）：定义 → 何时用（叙事功能）→ **易混淆"近亲"辨析**（如 dolly vs dolly zoom）→ 片例（Vertigo/Jaws/Goodfellas 等）→ 可直接粘贴的 prompt 骨架 + 失败模式提示（"你只是 zoom 了"）。
- **机器可读程度**：产品内置 CLI（`npm install -g melies`，GitHub: melies-co/cli），agent 可拿 `--json` 结构化输出——但**技法库本体是网页/产品资产，不是开源 JSON/YAML 仓库**；"380 种机器可读知识库被 Agent 检索消费"的原始说法**未能验证**（可考数字是 424，形态是产品页卡片+CLI）。
- 来源（2026-10-04）：https://artrealmai.com/article/melies-cinematic-techniques-ai-video （类目计数表）；https://github.com/melies-co/cli/blob/HEAD/./SKILL.md （CLI/JSON 输出）；https://turbo0.com/item/melies （产品形态）
- **对本项目**：闭源商业产品，**文本不可搬运，但其"卡片五段式结构"是免费的公共方法论**——正是我们给 N3 控制图派生建自研技法库的现成蓝本。

### 2.1 智象未来 HD-AgentOS + vivago R1（国内，WAIC 2026 发布）

- **架构**：自研 **HD-AgentOS 智能体操作系统，三层耦合**——资源层（模型/工具/数据底层调用）、系统层（智能体调度、多单元协同、全流程安全治理）、能力层（模型能力封装为面向影视/营销的标准化技能）；vivago R1 为该体系首个产品：**全球首款（官方口径）支持无限时长视频生成的多模态创作智能体**，特性概括为"长、长、稳"（无限时长 / 长任务思考——叙事构思·镜头排布·风格校准 / 高稳定生成）。多智能体协同把"理解任务—构思故事线—创作分镜—生成素材—输出长视频"全链路原子化封装。
- **机制**：解决行业三大痛点（时长受限 15–30 秒、逻辑混乱——画面跳变/人设崩塌/叙事断层、效果不稳）；以 AgentOS 全流程调度治理换取"内容商用可用成功率 85%"。
- **数值核实**：
  - "85% 商用可用成功率"：**多源一致转述官方口径属实**（新华网/环球网/中国经济网/凤凰网四家均报），但**均为厂商自报、无第三方验证**，采信需标注口径；
  - "无限时长"：官方宣称，无第三方实测，**未验证**；
  - **梅涛"多智能体集群协同+配套操作系统"言论出处已锁定**：新华网 2026-07-19 WAIC 中国信通院配套论坛报道，原话"单一智能体难以完成复杂跨链路任务，多智能体集群协同搭配配套操作系统，是打通 AI 商业化落地的关键支撑"。
- **可借鉴**：三层架构与我们 llm_gateway（资源=模型档位 / 系统=crew_bus 调度 / 能力=操作员 SKILL.md 装配）同构，**互证我们的分层是行业收敛方向**；"能力层标准化技能封装"即我们 SKILL.md 装配器的国内背书。
- **差异**：闭源商业平台（模型+平台一体），无限时长靠云端连续生成；我们走白模+控制图的确定性管线，可控性思路不同；其 85% 口径未公开评测集，不可直接对比我们 Retake 通过率。

### 2.2 CrewAI Hierarchical Process

- **架构/机制**（官方文档核实，2026-10-04）：`process=Process.hierarchical` 下自动（或用 `manager_agent` 显式指定）创建 **manager agent**，职能为**规划、按成员角色/能力动态委派任务、验证产出质量**；任务不预分配；必须提供 `manager_llm` 或 `manager_agent`，否则 `kickoff()` 校验直接报错（新手最常见坑）。委派机制：manager 读任务描述→单次 LLM 调用决定路由给谁→委派消息下发→回收验证。配 `planning=True` 可先出计划再委派。
- **成本与适用边界**（社区深度指南）：manager 参与每一次决策，token 消耗显著高于 sequential、执行路径更难追踪、整体吞吐受 manager 模型单点制约；**经验法则："stay sequential until you can name the specific decision you want made at runtime"**——能说出需要运行时临场决策的具体问题，才配用层级制。
- **可借鉴**：①"manager 只委派/验证、不亲自执行"的角色分离，可用于导演操作员与执行操作员的关系定义；②动态委派仅适合我们的**重生成仲裁**（写实化岗与场记 QC 分歧时路由），确定性 N1→N5 主链必须保持 sequential——与我们现有 crew_bus 顺序总线一致，无需改架构。
- **差异**：CrewAI 层级制无"预算/台账"概念，其验证靠 manager LLM 主观判断；我们的 Retake 预算制 + 契约校验更硬。另注意旧稿 A3 决策（记忆全关、契约即记忆）与 CrewAI 记忆体系（短期/长期/实体/上下文四类）取向不同，维持我们决策不变。
- **URL**（查询日期 2026-10-04）：官方 FAQ https://docs.crewai.com/edge/en/enterprise/resources/frequently-asked-questions ；官方层级流程文档 https://docs.crewai.com/edge/ar/learn/hierarchical-process ；委派机制与坑位实测 https://theneuralbase.com/crewai/learn/intermediate/how-the-manager-delegates-tasks ；成本权衡 https://www.spillwave.com/guides/crewai/part-03-sequential-vs-hierarchical

### 2.3 Microsoft Agent Framework 1.0 GA

- **核实结论**：
  - **2026-04-03 GA 属实**（官方 devblogs 宣布 1.0 for .NET and Python：stable APIs + 长期支持承诺；第三方评测/百科/工具站三方一致确认该日期）；
  - **Semantic Kernel + AutoGen 合并为单一开源 SDK 属实**；MIT License；.NET + Python（Go 公测）；
  - **原生 MCP + A2A 属实**（另有 AG-UI、OpenAPI）；
  - **"Orchestrator/Sub-agent 分离"的说法需修正表述**：官方术语是**编排模式（orchestrations）**——sequential / concurrent / handoff / group chat / Magentic-One 五种，全部支持流式、checkpoint、human-in-the-loop、暂停恢复；外加 **Workflows 图引擎**（agent+函数组图、条件分支、并行扇出汇聚、断点续跑）。没有名为"Orchestrator 角色与 Sub-agent 分离"的独立卖点——它是"编排模式库"而非"管理岗分离"。
- **可借鉴**：①Workflows 的 **checkpointing + hydration（中断后恢复长任务）**——我们 N2→N4 长链批跑需要这个能力形态；②**YAML 声明式 agent/工作流**（指令、工具、记忆、编排拓扑版本化）——与我们 SKILL.md+契约文档版本化的方向一致；③五种编排模式可作为 crew_bus 扩展时的选型菜单。
- **差异**：MAF 是通用 agent 框架，无影视领域任何概念；连接器以国外云为主（Foundry/Azure OpenAI/Claude/Bedrock/Gemini，也含 Ollama）——**仅借鉴模式，不引入框架**（我们 0 国外付费端点纪律不变，且 CrewAI 已在栈内，无迁移动因）。

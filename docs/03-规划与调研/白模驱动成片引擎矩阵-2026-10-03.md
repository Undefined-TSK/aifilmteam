# 白模动画→成片引擎矩阵调研

> **调研人**：v2v-engine-matrix · 2026-10-03（第十七轮派生任务 2，承接 R17-1「白模双环节=项目最大特色」）
> **性质**：纯调研，只写本文件与《额度耗尽计划-2026-10-03.md》，不改任何其他文件；未调用任何付费 API，全部以官方文档/公开资料核实。
> **基线**：shot_spec.schema.json:225 四枚举（fal_ltx23_render_to_real / jimeng_seedance25_blockout / higgsfield_blender / local_wan22_fallback）为骨架**扩展融合，不推翻**（K-REV-3：本地优先+云端备选；R17-5：多元共存）。白模输入形态以 01-blender-blockout.md D6b 为准：**整段白模 MP4（832×480/24fps）+ 帧序列 + EXR(Z/Normal/IndexOB) + camera_sidecar**。

## 一、核心结论（老板问的三个问题先行）

1. **最适配白模管线的云端引擎 = 百炼 `wanx2.1-vace-plus`（video_repainting）**：唯一在官方文档明确支持把**整段输入视频自动提取控制信号**（`control_condition=posebodyface / posebody / depth / scribble`）后重绘的 API——白模 MP4 直喂、无需用户逐帧上传姿态/深度序列，输出与输入时长一致（≤5s）、720P 档、无声。这是"白模动画视频完整输入→成片"的最短云端路径，但只有 **50 次额度（10/27）**。
2. **最适配白模管线的本地引擎 = ComfyUI + Wan2.1-VACE-1.3B（已补齐 4.3GB）**：全球唯一能吃**显式 EXR 逐帧控制信号**（我们白模本来就渲 Z/Normal/IndexOB）的路线，12GB 显存 480p/约 5s（121 帧已有实测先例）可跑，零边际成本无限迭代；wan2.2 14B GGUF q8_0（~11GB）可作 480p 质量升档。
3. **外部长板 = Runway Aleph（in-context 视频编辑）+ Kling Motion Control（参考动作视频驱动）+ Seedance 2.0（多参考视频）**：三者都能"吃视频出视频"，但均无逐帧姿态/深度显式控制，对白模是**语义级跟随**而非结构级锁定；列为二轮深调候选（reserved，按 K-REV-3 不索取 Key）。

## 二、对比矩阵

> 白模输入形态缩写：**整段V**=整段白模视频直喂；**首帧**=白模首帧图；**首尾帧**=白模首/尾帧两图；**逐帧控制**=显式姿态/深度/线稿序列上传；**自动提取**=引擎自己从输入视频抽控制信号；**多参考**=多图/多视频参考注入。
> 适用度：**A**=白模管线主力（结构级可控或免费无限）；**B**=进阶对照/升档（有价值但控制松或贵）；**C**=不优先（额度太小/控制太松/需重建工作流）。

**核实要点（官方文档级）**：
- `wanx2.1-vace-plus`：`control_condition` 枚举 {`posebodyface`, `posebody`, `depth`, `scribble`}——**控制信号由服务端从 video_url 自动提取，不接受用户上传的逐帧控制图序列**（与本地 VACE 的本质差异）。`function` 五档：image_reference / video_repainting / video_edit / video_extension / video_outpainting。size 五档 720P 级，duration 固定 5s（重绘/编辑/外扩输出时长=输入时长，超 5s 取前 5s）。
- `wan2.7-i2v`：media 白名单组合 first_frame / +last_frame / +driving_audio / first_clip(+last_frame)；driving_audio 用于**口型对齐**；图 240-8000px ≤20MB。
- `wan3.0-video`：单次 [2,30]s（-1=智能时长）、`parameters.audio` 默认 true（台词/BGM/音效自动生成）、media[] 上限 10 图+5 视频+5 音频。

## 四、白模管线推荐路由（一镜的决策树）

```
白模 MP4 + PNG/EXR/蒙版/sidecar（832×480/24fps）
├─ R4 验证/迭代期（免费无限）→ 本地 VACE-1.3B（EXR Z→深度控制，480p）
├─ 质量升档（免费额度内）→ 百炼 vace-plus video_repainting(control_condition=depth)   ← 50 次配额
│                          → 百炼 wan2.7-i2v（首尾帧+driving_audio 口型）            ← 对白镜头
│                          → 百炼 wan3.0-video（30s 整段+音画，雨夜寻猫样片）          ← 11/05 前烧完
├─ 付费升档（B9 四条件门后）→ fal wan2.2-v2v（$0.04/s@480p，与本地同源）→ Kling Motion Control（表演驱动）
└─ 后处理（全部免费额度）→ liveportrait/videoretalk（口型）+ video-style-transform（风格）+ RIFE 插帧（本地）
```

**发现的三大能力缺口**（含额度耗尽计划的最重要输入）：
1. **云端无一家接受显式逐帧控制信号上传**——姿态/深度序列只能在本地 VACE 消费；云端"白模→成片"都是自动提取或语义跟随。→ EXR→控制图派生工具（M7 本地）是管线唯一不可替代件。
2. **5-15s 单镜上限 vs 30s 孤例**：除 wan3.0-video（30s）外全部 ≤15s，16 镜全片必须靠 kf2v/首尾帧/续写拼接——首尾帧链路（kf2v-plus 200 次 + wan2.2-kf2v 50 + wan2.7-i2v 50）是时长天花板的主要突破口，且`returnLastFrame`/尾帧回接是标准做法（Seedance 有显式 returnLastFrame 参数，百炼可从成片抽尾帧回喂）。
3. **12GB 本地 720p 无 VACE**：VACE 只有 1.3B（480p 档）；720p 结构级控制只能靠云端 vace-plus 50 次或付费。→ 白模母版维持 832×480（D2 拍板不变），720p/1080p 走云端+超分。
